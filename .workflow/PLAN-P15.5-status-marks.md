Facts found while planning (2026-11-15):

- `serve` serves `getErrorFrame()` (`src/showcases/`) in place of any showcase with an error, files or not (`getServedFrames()`, `src/cli/serve/`, _`D558`_ (PLAN-P15.2-checks-and-issues.md)).
- `getShownHostInformation()` (`src/vite/`) ships only the showcases with a showcase frame: a showcase that doesn't build is shown today only through its error frame.
- `buildShowcases()` returns each showcase's errors (`errors`, by showcase id) and checks (`checks`), but its warnings as one flat list; each issue is placed by `getBuildIssue()` at the documentation file's line for a virtual file, and its message prefixed with the showcase and its check, for the command line.
- `getShownChange()` (`src/cli/serve/`) reloads the whole page on any change but the showcase frames' and tabs' URLs; `applyShowcaseUrls()` (`src/app/host/`) applies those.
- The frame script posts `ready` once the page has loaded (`src/frame/`); the console's state (`src/app/console/`) counts only the unseen errors (cleared when the console panel opens), not the warnings or errors since the load.
- The code block's gutter (`src/app/code/`) is one `pre` of line numbers: no line can be styled on its own yet.
- The header bar (`src/app/code-pane/`, _`D575`_ (PLAN-P15.4-views.md)) has its left empty for the status marks.
