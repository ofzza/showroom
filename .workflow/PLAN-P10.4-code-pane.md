Not in _`P10.4`_: the console (_`P10.5`_).

Facts found while planning (2026-11-14):

- `ShownShowcase` (`src/app/host/`) carries `id`, `documentation`, `offset` and `url`; `getShownHostInformation()` (`src/vite/`) builds it, called by `build()` and by `serve` (its first run and the host watcher's). The shown host information ships the documentation files' content and the linked files, but no virtual file.
- `Showcase` (`src/host/`) has `kind`, `display`, `entry` (a code block showcase's virtual file, or a linked showcase's file) and `include` (root-relative paths), since _`P10.3`_; an included file is a virtual file, a documentation file or a linked file (_`D393`_, _`D395`_, _`D396`_ (PLAN-P10.3-keys.md)).
- `remarkShowcaseFrames()` (`src/app/showcases/`) places each showcase frame before the nearest flow block holding its entry point, by offset, with the ancestors of each node at hand.
- `serve` decides between a full reload and the `showroom:showcases` event with `getShownChange()`, which compares the shown host information without the showcase frames' URLs; `applyShowcaseUrls()` applies the event's URLs in the showroom. A linked file's content change changes nothing shown, so nothing is sent (_`O67`_).
- The linked files middleware (`src/vite/`) ignores a request's query, so a `?hash=` on a linked file's URL needs no change there.
- The modal (`src/app/file-modal/`) fetches a linked file with `fetchLinkedFile()` when it opens, and renders it with `HighlightedCode` (`src/app/code/`), the shared `CodeBlock` with its gutter and copy button.
- `@griffel/core` 1.21.4 is installed, and handles `@container` rules (_`K17`_'s note).

## Steps

1. **The shown host information** (`src/app/host/`, `src/vite/`, `src/cli/serve/`, `src/cli/build/`) (_`D365`_, _`D375`_, _`D404`_, _`D406`_, _`D411`_, _`D412`_): `ShownShowcase` gains `display` and `tabs`; `ShownTab` holds its `label`, `path` (root-relative), `language` (`getLanguage()`) and its source: `virtual` (the virtual file's content), `documentation` (looked up in the shown documentation files), `file` (its `url`, `files/<path>`, with `?hash=<hash>` when it is text, and `text`) or `missing` (a linked showcase's entry point `check` didn't collect as a linked file, _`D411`_). Labels: a code block showcase's entry point its extension upper-cased (_`D412`_); every other tab its path relative to the documentation file, without `./` (`clock.css`, `../shared/x.css`), by a helper in `src/markdown/` beside `resolvePath()`. `getShownHostInformation(host, frames, hashes)` stays pure: it builds the tabs from `entry` and `include`, looking each path up in the virtual files, the documentation files, then the linked files, and takes the hashes of the text `file` tabs' contents (no hash for a file that isn't text: its tab only links to it, and a change of `text` already reloads). `build()` computes the hashes with a helper beside `getShownHostInformation()` (the hash function shared with the showcase frames'), and `createHostWatcher()` gets it as an injected option (`hashFiles`, defaulting to it), so its unit tests keep fakes. `getShownChange()` ignores the tabs' URLs as it does the showcase frames', and a changed tab URL goes out with the `showroom:showcases` event; `applyShowcaseUrls()` applies the tabs' URLs too (renamed if its name no longer fits), as `applyUpdate()` and `mount()` (`src/app/index.tsx`) do, their JSDoc updated.
2. **Placement** (`src/app/showcases/`) (_`D373`_): `remarkShowcaseFrames()` replaces a block's entry point (a code block showcase's fence, or the paragraph holding a linked showcase shown as a block) with a showcase block element, so its code is never also rendered as an ordinary code block; a linked showcase shown inline keeps its showcase frame before its paragraph. A showcase with no showcase frame (none in the shown showcases, e.g. `serve`'s first build throwing) leaves its fence or paragraph as plain Markdown. The Markdown component (`src/app/markdown/`) maps the element to the code pane's block.
3. **The code pane** (a new `src/app/code-pane/`) (_`D352`_–_`D356`_, _`D376`_, _`D378`_, _`D403`_, _`D405`_, _`D407`_–_`D409`_, _`D411`_, _`D413`_): first confirm that Griffel's `makeStyles` emits `containerType`, `contain` and `@container` as the spike's CSS was (if it doesn't, stop and propose a way); then the block as in _`D403`_, two elements, as a container query applies to the container's descendants only: the CSS container outside, the grid inside, holding the showcase frame (first, on the left side by side and above stacked, _`D413`_; never moved in the React tree, never stretched, `inert` at full, which drops any focus inside it) and the code pane; the cycling button its own element, so it stays while the code pane is hidden. Every state starts at half (_`D353`_), with the starting state a property, so the server-side rendering in the tests can render each. The code pane: a header row with the tab list (FluentUI's `TabList`, always shown, _`D408`_) and the cycling button at its right end (_`D407`_; floating over the frame's top-right corner while hidden), labelled by the state it switches to ("Show the code", "Show the code over the showcase", "Hide the code"); below it, the selected tab's code, a `tabpanel` labelled by its tab, through `HighlightedCode`, whose `CodeBlock` gains an optional height bound so its own scroller scrolls both ways, its copy button outside the scroll. The minimum of 6 and the maximum of 20 count code lines only (the header and padding aside); the code pane stacks below a 720 px block (the container is the block, so one in a list item or a blockquote stacks earlier than the column's width says) (_`D405`_). The showcase frame's and the code block's own vertical margins are reset inside the block. A `file` tab is fetched by its URL the first time it is shown, and again when its URL changes, at once if shown, otherwise when next shown (_`D409`_): `fetchLinkedFile()` and `useLinkedFileContent()` (`src/app/file-modal/`) take a URL. A tab that isn't text says it can't be shown there, with a link opening it directly (_`D378`_); a `missing` tab says the file isn't copied into the showroom, with no link (_`D411`_).
4. **The modal's tabs** (`src/app/markdown/`, `src/app/file-modal/`) (_`D362`_, _`D378`_, _`D408`_, _`O64`_): a link to a linked showcase shown inline knows its showcase by its offset (react-markdown's `node.position.start.offset`); when it has included files, `LinkedFileDialog` shows its tabs (each titled with its path; a `file` tab with its "Open in a new tab" link, a virtual or documentation tab without one; one that isn't text, or `missing`, as in step 3), fetched as in step 3; without included files, and for every other link to a linked file, the modal is as today. A linked showcase shown inline whose entry point isn't text keeps opening it in a new tab, so its modal and tabs never show (accepted).
5. **Tests** (_`O65`_): `src/markdown/` (the relative-path helper); `src/vite/` (the tabs built for every kind of source, `missing` among them; the labels; the hashes, none for a file that isn't text); `src/cli/serve/` (`getShownChange()`; the host watcher, with a fake `hashFiles`, sending a changed tab URL as an event, not a reload); `src/app/host/` and `src/app/index.test.tsx` (applying the tabs' URLs: `applyShowcaseUrls()`, `applyUpdate()` and the store with a change to a tab's URL alone); `src/app/showcases/` (placing blocks: a fence, a paragraph in a list item and a blockquote, no duplicated code block; inline unchanged; a showcase without a showcase frame left as plain Markdown); `src/app/code-pane/` (rendered on the server: the block's structure and order, each starting state with its button's label and the frame's `inert` at full, the tab list with one and several tabs and their labels, the tab panel, a tab that isn't text, a `missing` tab; fetching by URL with a stubbed `fetch`); `src/app/code/` (the height bound); `src/app/markdown/` and `src/app/file-modal/` (the modal's tabs, one that isn't text; a showcase without included files unchanged); `e2e`'s `build` and the `serve` tier on copies of the `showcase-keys` fixture: the shown host information carries the tabs (`files/<path>?hash=<hex>` in the bundle, and in the virtual module), and a `file` tab's URL serves its file. The user checks the code pane in a browser (the states, stacking, the frame never reloading, tabs, the modal's tabs).
6. **Documentation** (_`D370`_, _`D381`_, _`D398`_ (PLAN-P10.3-keys.md), _`D410`_): `README.md`: sections on `block` and `include=`, each example followed by it, live (their files in `examples/`), the code pane described (its states, tabs, sizes; tabs show only included files, never what a showcase imports (_`D363`_)), the syntax cheat-sheet (a plain text table, no live showcases); › Showcase frames (a block replaces its fence or paragraph); › `showroom serve` (a changed included file updates its tab without a reload); each showcase adapter example's first showcase shown as a block, in the example and in `README.md`'s copy, its Markdown example included (_`D410`_); `ShownShowcase` isn't exported, so `# Usage` changes only where it describes what the showroom shows. `AGENTS.md`: Layout (`src/app/code-pane/`, and the entries of `src/app/showcases/` and `src/app/file-modal/`), Testing (the code pane, the modal's tabs), the narrow layout gotcha (a container query, the second way allowed), the live markers gotcha (the cheat-sheet's exemption, _`D370`_; the showcase adapter examples' first showcases as blocks, _`D410`_), a gotcha on the tabs' `?hash=`; `CONTRIBUTE.md`: the project structure (`src/app/code-pane/`), the architecture (the placement of blocks, the modal's tabs, the `showroom:showcases` event carrying the tabs' URLs), and the Glossary's "Code pane" if the cycling button changes what it says. ## Decisions

- _`D403`_ (`live`; resolves _`K17`_ and _`K18`_ (SPEC-pitfalls.md) for the layout; _`D385`_'s spike (PLAN-P10-presentation.md), the user: "Works, use it"): **The code pane's layout is CSS alone, around an iframe that never moves**: the block is a CSS container (`container-type: inline-size`) holding a grid with the showcase frame and the code pane; the three states only change the grid's template (half: two columns; hidden: the frame alone, the code pane not displayed; full: the code pane in the frame's cell, over it, the frame `inert`), so the iframe is never moved in the React tree, and never reloads; a container query (`@container (max-width: …)`) stacks the code pane below the frame when the documentation column is narrow, with no script reading a width (`AGENTS.md` › the narrow layout is switched by CSS alone). The frame keeps its own height (`align-self: start`: never stretched to the row); side by side the code pane never sizes the row (`contain: size`), filling the row the frame or the minimum sets, and scrolling; stacked, and at full, it takes its content's height between the minimum and the maximum.
  - Evidence: Spike 2026-11-13 (`./.workflow/.temp/spike-code-pane/`, a static page and a frame page reporting its height as the frame script does, with its growth guard), checked by the user in a browser and measured with Playwright (Chromium): through every state change and column width the frame loaded once, and its own state (a click counter) was kept; side by side, a 150 px frame sat in a row of the minimum (8 lines), unstretched; full capped the code at the maximum (24 lines), scrolling; below a 640 px column the code pane stacked under the frame; a frame sized to its viewport (`100vh`) grew a few steps until the existing guard (`MAX_REPEATED_GROWTHS`) stopped it, unstretched by the code pane, which followed its height side by side. The numbers (8 and 24 lines, 640 px) were the spike's, not yet decided (_`O63`_). Griffel's support of `@container` and `contain` in `makeStyles` is still to confirm in the showroom (_`K17`_'s note: `@griffel/core` 1.21.4 handles `@container` rules).
- _`D404`_ (`live`; resolves _`O62`_ (SPEC-S10-presentation.md) for the shown host information; Q1, option chosen: "Tabs built in Node (Rec.)"): **The shown showcase carries its tabs, built in Node**: `ShownShowcase` gains `display` and `tabs`, each tab with its label (a code block showcase's entry point its language, e.g. "HTML"; every other tab its path relative to the documentation file, _`D356`_), its root-relative path, its language and its source: a virtual file's content shipped inline (a code block showcase's entry point, an included virtual file), a documentation file looked up in the shown documentation files, or a linked file fetched from its URL, with whether it is text. Only the virtual files a showcase shows are shipped. Rejected: shipping `kind`, `entry`, `include` and every virtual file, and resolving the tabs in the showroom.
- _`D405`_ (`live`; resolves _`O63`_ (SPEC-S10-presentation.md); Q2, option chosen: "6 / 20 / 720 px"): **The code pane's sizes: at least 6 lines, at most 20, stacked below a 720 px documentation column**. Rejected: the spike's 8 / 24 / 640 px (the recommendation); 10 / 30 / 600 px.
- _`D406`_ (`live`; resolves _`O67`_ (PLAN-P10-presentation.md); Q3, option chosen: "Hash in tab URL (Rec.)"): **A linked file's tab carries its content's hash in its URL** (`files/<path>?hash=<hash>`), as showcase frames do: `serve` and `build` hash the files of `file` tabs; a changed hash alone goes out with the `showroom:showcases` event, never a full reload, and the tab fetches again when its URL changes. Rejected: fetching again on every tab selection (a tab on screen stays stale); a full reload on any change of an included file's content (every showcase frame reloads, every code pane's state resets).
- _`D407`_ (`live`; changes _`D356`_ (SPEC-S10-presentation.md), _`R29`_; Q4, option chosen: "One cycling button"): **The code pane's state is switched by one cycling button**, hidden → half → full → hidden, labelled with the state it switches to (tooltip and `aria-label`), in the code pane's top-right corner, and floating over the showcase frame's top-right corner while the code pane is hidden. Rejected: a header strip across the block with the tabs and three toggle buttons, one per state (the recommendation).
- _`D408`_ (`live`; refines _`D356`_, _`D362`_ (SPEC-S10-presentation.md); Q5, option chosen: "Pane always, modal >1 (Rec.)"): **The code pane always shows its tab list**, even with one tab, so every block names its file or language; **the modal shows tabs only for a linked showcase shown inline with included files**: without them, and for any other link to a linked file, it is as today. Rejected: tabs only with more than one file, in both; tabs always, in both.
- _`D409`_ (`live`; Q6, option chosen: "Lazily, when shown (Rec.)"): **A linked file's tab is fetched the first time it is shown**, kept while the page is shown, and fetched again when its URL changes (_`D406`_); a linked showcase shown as a block fetches its entry point's tab at mount, as it is selected first. Rejected: fetching every tab when its block mounts.
- _`D410`_ (`live`; refines _`D381`_ (SPEC-S10-presentation.md); Q7, option chosen: "Blocks in both (Rec.)"): **`README.md`'s copies of the showcase adapter examples' first showcases are blocks too**, their Markdown examples showing the `block` key, as the examples' own are. Rejected: blocks in the examples only.

- _`D411`_ (`live`; review 2026-11-14 #2, QA, option chosen: "Keep tab, say why (Rec.)"): **A tab whose file isn't copied into the showroom stays, saying so**: a linked showcase's entry point `check` leaves out of the linked files with a warning (in the output folder, or outside the root through its real path), whose showcase still builds, keeps its tab, which says the file isn't copied into the showroom, with no link. Rejected: a `check` error for `block` on such an entry point; an error for every linked showcase; dropping the tab.
- _`D412`_ (`live`; refines _`D356`_ (SPEC-S10-presentation.md), _`R30`_; review 2026-11-14 #4, QB, option chosen: "Extension, upper-cased (Rec.)"): **A code block showcase's entry tab is labelled by its entry point's extension, upper-cased** ("HTML", "TS", "TSX", "JSON"), the extension being the fence's language as normalised (`typescript` is "TS"). Rejected: a map of display names ("TypeScript"); the fence's language as written (a field to keep).
- _`D413`_ (`live`; refines _`D352`_ (SPEC-S10-presentation.md), _`R30`_; review 2026-11-14, QC, option chosen: "Frame left, code right (Rec.)"): **Side by side, the showcase frame is on the left and the code pane on the right**, the order stacked has (the frame above, the code pane below, _`D355`_), so the document's and the reading order is the same in both. Rejected: the code pane on the left.
