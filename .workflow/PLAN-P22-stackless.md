# _`P22`_ Host repositories without a stack adapter

approved 2026-11-18 (option chosen: "Approve and commit (Rec.)"), after its zero-context review (_`D873`_–_`D876`_); implemented 2026-11-18 (option chosen: "Approve and commit (Rec.)")

_`S18`_ (SPEC.md): `showroom.json`'s `project` may be an object holding the project information, and then no stack adapter is used; `stack` is then optional, names the stack for showcase adapters (`custom` when left out), and may not be a built-in stack adapter's name. One segment, with no child segments.

## Decisions

- _`D869`_ (`live`, refined by _`D876`_, changed by _`D882`_ (SPEC.md); Q1, option chosen: "Pass the object"): **Showcase adapters get the object as `project`**: `ShowcaseBuildRequest.project` and `ShowcaseCheckContext.project` become `string | ProjectInformation`, `showroom.json`'s `project` as written (a path, or the object). No built-in showcase adapter reads it, so only custom ones see the change; the showcase adapter interface is experimental, and `CHANGELOG.md` names the change. Rejected: leaving it out with an object `project`.
- _`D870`_ (`live`, refined by _`D874`_, _`D876`_; Q2, option chosen: "validateConfiguration (Rec.)"): **`validateConfiguration()` checks all of _`S18`_'s rules**: the object's keys and types (_`D866`_ (SPEC.md)), `stack` required unless `project` is an object, and a built-in stack adapter's name refused with an object `project` (_`D867`_ (SPEC.md)), taking the names from `getStackAdapterNames()`. The exported `Configuration` type becomes `stack?: string` and `project?: string | ProjectInformation`. An unknown `stack` with a string `project`, or none, stays `check()`'s error, its message adding that a host repository whose stack has no stack adapter gives an object `project`. Rejected: leaving how `stack` and `project` combine to `check()`, which library users of `validateConfiguration()` would miss.
- _`D871`_ (`live`, refined by _`D873`_; Q3, option chosen: "Internal resolveStack() (Rec.)"): **An internal `resolveStack(configuration)` in `src/adapters/stack/`** (not re-exported from `src/index.ts`; `src/index.test.ts`'s export list guards it) returns the stack's name, its defaults (source root, ignore, code and documentation patterns: the stack adapter's, or `.` and empty lists with none) and the stack adapter, if any, or the unknown name's error. `check()` (the project information read only with a stack adapter, the object taken as is otherwise), `checkHost()`, `readIgnoreMatcher()`, `createIgnoreMatcher()` and `buildShowcases()` (the request's `stack`) use it in place of `getStackAdapter(configuration.stack)` and `configuration.stack`. Rejected: a hidden stack adapter returning the object (_`D865`_ (SPEC.md): none is used at all).
- _`D872`_ (`live`, refined by _`D875`_, _`D876`_; Q4, option chosen: "Java-like + custom adapter (Rec.)"): **Fixtures `test/fixtures/stackless/` and `stackless-unnamed/`**: a mock Java project (`pom.xml`, `src/main/java/…/*.java`, `README.md`) with an object `project` and `code: ["*.java"]`; `stackless` sets `stack: "java"`, `stackless-unnamed` leaves it out. Each has a small custom showcase adapter (`"type": "module"` in a `package.json` holding no `name`, which nothing reads) whose host check reports the `stack` and `project` it is given as a warning, so `check()`'s tests (with `trust: true`) show showcase adapters get `java`, or `custom`, and the object.

### The review's outcomes

From the zero-context review of 2026-11-18 (`./.workflow/.temp/review-p22/REVIEW.md`).

- _`D873`_ (`live`; refines _`D871`_; review 2026-11-18 #1, option chosen: "src/adapters/stack/resolve/ (Rec.)"): **`resolveStack()` lives in `src/adapters/stack/resolve/`** (`index.ts` and `index.test.ts`), which `src/adapters/stack/index.ts` doesn't re-export, as `src/index.ts` re-exports that module whole (`export *`); it imports `Configuration` with `import type`. `AGENTS.md`'s Layout and `CONTRIBUTE.md`'s project structure get the folder. Rejected: `src/cli/check/internal/`.
- _`D874`_ (`live`, changed by _`D877`_ (SPEC.md); refines _`D870`_, _`D867`_ (SPEC.md); review 2026-11-18 #7, option chosen: "Case-insensitive"): **A built-in stack adapter's name is refused with an object `project` whatever its case** (`TypeScript`, `DOTNET`), so no name that looks built-in reaches showcase adapters. Selecting a stack adapter stays case-sensitive, as now. Rejected: case-sensitive.
- _`D875`_ (`live`; refines _`D872`_, _`D866`_ (SPEC.md); review 2026-11-18 #2, option chosen: "Document it only"): **Nothing is ignored by default without a stack adapter, and the documentation says so**: `README.md`'s "Without a stack adapter" part and its Java example set `"ignore": [".git", "node_modules", "target"]`, saying why (otherwise `.git/` is walked and every `README` under `node_modules/` is a documentation file); the fixtures set the same `ignore`. Rejected: ignoring `.git` and `node_modules` by default without a stack adapter; always ignoring `.git`.
- _`D876`_ (`live`; refines _`D869`_, _`D870`_, _`D872`_; review 2026-11-18 #7–#10, option chosen: "Apply all (Rec.)"): **The validation's details, copies and the fixture's showcase**:
  - any object `project`, valid or not, makes `stack` optional, so only the object's own errors show; `stack: "custom"` given explicitly is allowed; an optional field of the object that's an empty string is an error, as `name`;
  - the object's errors name its field, as the navigation's do (e.g. `showroom.json: "project": "version" must be a non-empty string`, `showroom.json: "project": unknown key "sourceRoot"`), and an unknown key that is a top-level key's name (`sourceRoot`, `ignore`, `code`, `documentation`, …) adds that it belongs at the top level;
  - each showcase adapter's request and check context, and the host information's `project`, get a copy of the object, the host information's built from its validated fields only, so a showcase adapter changing what it's given changes nothing else;
  - `src/configuration/` imports `getStackAdapterNames()` from `src/adapters/stack/` at run time (no cycle: the stack adapters import only types);
  - each fixture's `README.md` holds a showcase of its custom showcase adapter, valid, so its host check runs; the tests check the code file index holds only the `.java` files.
