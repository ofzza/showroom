# _`P16`_ Showcases shown inline, in the sidebar

implemented 2026-11-15 (option chosen: "Approve and commit (Rec.)"); approved 2026-11-15 (option chosen: "Approve and commit (Rec.)"), without a zero-context review

## Goals

_`S12.1`_ (SPEC-S12-showcase-views.md): _`D513`_–_`D516`_; a linked showcase shown inline becomes a link opening the showcase in the sidebar, shown as a block shows it. Takes _`O87`_ (SPEC-S12-showcase-views.md). Planned after _`P15`_, as a segment of its own (_`D542`_ (PLAN-P15-showcase-views.md)).

Facts found while planning (2026-11-15):

- A linked showcase shown inline gets its showcase frame, with a header bar and issue list (`InlineShowcase`, `src/app/code-pane/`), placed before its paragraph by the remark plugin (`src/app/showcases/`); its link opens the code sidebar with its tabs only when it has more than one tab, otherwise the file alone (`MarkdownLink`, `src/app/markdown/`).
- `view=` on an inline link is a `check` error (`src/markdown/`), and `check()` gives it `['demo']` (_`D526`_ (SPEC-S12-showcase-views.md), _`D572`_ (PLAN-P15.4-views.md)).
- The code sidebar (`src/app/code-sidebar/`) is FluentUI's `OverlayDrawer`, 66vw wide (400–1200 px), its content rendered only while open; the code pane stacks below 720 px by a container query, so in the sidebar it is mostly stacked.
- `loadsShowcaseFrame()` (`src/vite/`) ships no showcase frame for a showcase with neither `demo` nor `console`, so an inline showcase with no views ships none.
- `README.md` holds one live linked showcase shown inline (`[Formatted figures](./examples/figures.html 'showcase')`).

## Decisions

The draft's choices 1–12 (`./.workflow/.temp/questions-p16/QUESTIONS.md`), options chosen: the recommendations, except Q3 ("Start below the views").

- _`D616`_ (`live`; refines _`D514`_ (SPEC-S12-showcase-views.md); resolves _`O87`_'s first half; supersedes _`D593`_ (PLAN-P15.5-status-marks.md); Q2): **The sidebar shows the block itself**: `ShowcaseBlock` gains a sidebar placement, so the two can't drift; the sidebar's header is the block's header bar (status marks, cycling button) with the × button at its end; then the issue list, the views, and the code pane, whose header holds the tab list, the "Open in a new tab" link (a real file's tab) and the copy button. `InlineShowcase` is removed. Rejected: _`D475`_'s header (tab list, link, ×) kept, with the status marks and issue list at the top of the body.
- _`D617`_ (`live`, refined by _`D627`_, changed by _`D628`_; refines _`D514`_ (SPEC-S12-showcase-views.md); Q3, option chosen: "Start below the views"): **The code pane's states in the sidebar**: with no views (`none`), the tabs alone, with no cycling button; with views, it opens with the code pane below (or beside) the views, then cycles to filling the sidebar, then hidden, then below again; while it fills the sidebar the views stay mounted, hidden as _`D570`_ (PLAN-P15.4-views.md) runs a showcase frame hidden, so the showcase frame never reloads. Rejected: starting hidden, as a block does.
- _`D618`_ (`live`; refines _`D514`_ (SPEC-S12-showcase-views.md); resolves _`O87`_'s second half; Q4): **Closing the sidebar unloads the showcase**: its showcase frame is removed, its console and `runtime` mark reset; reopening loads it afresh. Rejected: kept mounted while closed (the showcase running unseen).
- _`D619`_ (`live`; refines _`D514`_ (SPEC-S12-showcase-views.md); supersedes _`D526`_ (SPEC-S12-showcase-views.md); changes _`D572`_ (PLAN-P15.4-views.md); Q5): **`view=` on an inline link takes any views**; without it, `Showcase.views` is `['none']`, with no layered defaults (neither the showcase adapter's nor `showcaseViews`); `view=none` with `include=` is allowed inline, as the sidebar shows the tabs; _`D526`_'s error and _`D572`_'s `['demo']` for inline are retired. Rejected: an empty list `[]` as the default.
- _`D620`_ (`live`; refines _`D513`_ (SPEC-S12-showcase-views.md); Q6): **Every link to an inline showcase opens the sidebar with the showcase** (one tab or several, views or none), so its status marks and issues are always there; its `href` stays the entry point's URL, so a modifier-click or the browser's menu still opens the file in a new tab. Rejected: the file alone for one tab and no views.
- _`D621`_ (`live`; refines _`D516`_ (SPEC-S12-showcase-views.md); Q7): **The inline showcase link's icon is FluentUI's `Play16Regular`**, before the text, inside the `<a>`; a linked file's link keeps `Code16Regular`, moved before the text too. Rejected: `Flash16Regular`, `PanelRight16Regular`.
- _`D622`_ (`live`; refines _`D516`_ (SPEC-S12-showcase-views.md); Q8): **The `border-bottom` underline is only on links with an icon** (linked files and inline showcases); other links keep FluentUI's own underline. Rejected: on every link in rendered Markdown.
- _`D623`_ (`live`; refines _`D515`_ (SPEC-S12-showcase-views.md); Q9): **The code sidebar is renamed "Showcase sidebar"**: `src/app/code-sidebar/` → `src/app/showcase-sidebar/`, `CodeSidebar*` → `ShowcaseSidebar*`, `CODE_SIDEBAR_*` → `SHOWCASE_SIDEBAR_*`, and every comment and document (earlier workflow files keep their wording, as history). Rejected: "Sidebar".
- _`D624`_ (`live`; refines _`D512`_ (SPEC-S12-showcase-views.md); Q10): **`README.md`'s live inline showcase gains `view=demo`** (`[Formatted figures](./examples/figures.html 'showcase view=demo')`), so its sidebar shows it running; the prose names the marker as written (_`D607`_ (PLAN-P15.6-included-keywords.md)). Rejected: left with no views.
- _`D625`_ (`live`; Q11): **Tests and documentation**: unit tests in `src/markdown/` (`view=` inline, the default), `src/cli/check/` (the `showcase-views` fixture gains inline cases; `showcase-views-errors` loses the inline error), `src/app/showcases/` (no showcase frame placed for inline), `src/app/markdown/` (the icons before the text, the live icon, every inline link opening the sidebar), `src/app/code-pane/` (the sidebar placement rendered on the server in each state, no cycling button with no views), `src/vite/` (no URL for an inline showcase with neither `demo` nor `console`); no new fixture, `e2e` or `serve` test. `README.md` (inline showcases, the cheat-sheet rows, the code pane's states, the rename), `CONTRIBUTE.md` (architecture, Glossary), `AGENTS.md` (Layout, Testing, gotchas). Rejected: an `e2e` test of `build()` shipping an inline showcase with `view=demo`.
- _`D626`_ (`live`; refines _`D524`_, _`D536`_ (SPEC-S12-showcase-views.md); Q12): **_`P16`_'s Glossary changes**, **PROPOSED** at the checkpoint: **Code sidebar** renamed **Showcase sidebar**: "the panel opening from the right over the showroom that shows a linked file's content, highlighted, or a linked showcase shown inline as a block shows it"; **Linked showcase**'s "shown inline" redefined as "a link opening it in the showcase sidebar"; **Linked file**, **Included file** and **Code pane** follow the rename; no new term. Rejected: a new term **Showcase link**.

At the checkpoint, the user's browser check found every linked showcase shown inline opening an empty showcase sidebar: the block, a container query's container, was 0 px wide in FluentUI's drawer (fixed with `width: 100%`, a gotcha in `AGENTS.md`); then the code pane's header cut off beside the views. Options chosen: _`D626`_'s Glossary changes "Accept (Rec.)", with the Code pane's "below or beside the views" made "below the views" by _`D627`_; the user, for the code pane's header: "In the sidebar, always place the code pane below (not next to) the showcase(s)".

- _`D627`_ (`live`; refines _`D617`_; checkpoint): **In the showcase sidebar, the code pane's half state is always below the views**, whatever the showcase sidebar's width (never beside them, so its header, with its tabs, the "Open in a new tab" link and the copy button, has the showcase sidebar's width). Rejected: an icon-only "Open in a new tab" link; leaving the header scrolling.

Then, still at the checkpoint, the user: "In the sidebar (when displaying a inline showcase) instead of a 3-state button toggling between code-pane being hidden/50:50/full-screen, let's have a different 2-state button toggling between the showcases being expanded/collapsed."

- _`D628`_ (`live`; changes _`D617`_; refines _`D514`_ (SPEC-S12-showcase-views.md); checkpoint): **In the showcase sidebar, the code pane is always shown, and a two-state button toggles the views**: expanded (the start: the views, the code pane below them, _`D627`_) or collapsed (the views running hidden, as _`D570`_ (PLAN-P15.4-views.md) runs a showcase frame hidden, the code pane filling the showcase sidebar); labelled "Collapse the showcase" or "Expand the showcase", with `aria-expanded`, and a chevron up or down; with no views, no button. It replaces _`D617`_'s cycle there (no hidden state); a block on a page keeps its three states.

Then the user, for a block on a page: "Only when in 50:50 model, I would want to replace the "open in sidebar" icon with 2 icons: "open in sidebar" on the left (working exactly as it is now, and a "close" icon, taking you back to hidden, so that you don't have to toggle through the sidebar mode just to close the code pane".

- _`D629`_ (`live`; refines _`D477`_ (SPEC-S10-presentation.md); checkpoint): **A block's half state has two buttons in its header bar**: the cycling button ("Show the code in a sidebar", as before), then, right of it, a "close" button ("Hide the code") switching the code pane straight back to hidden; the hidden and sidebar states keep theirs as they are. Not in the showcase sidebar, whose toggle is _`D628`_'s.
