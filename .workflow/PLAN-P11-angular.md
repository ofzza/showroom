## Goals

The `angular` built-in showcase adapter (_`D97`_, SPEC-S6-showcases.md), in the format _`S6.4`_ (SPEC-S6-showcases.md) sets (_`D439`_–_`D446`_): compiled ahead of time by the host repository's own `@angular/compiler-cli`, before `showroom`'s Vite bundles it, on top of the `ts` showcase adapter's build (_`P7.1`_ (PLAN-P7.1-ts.md)), working in `check --showcases`, `build` and `serve` (_`D82`_, _`D102`_, SPEC-S6-showcases.md); with its showcase adapter example, as every new showcase adapter has (_`D304`_, SPEC.md).

## Child segments

Each is planned, approved, implemented and checkpointed on its own, in this order (_`D447`_):

- **_`P11.1`_ The `angular` showcase adapter** (approved 2026-11-14; [See The `angular` showcase adapter](./PLAN-P11.1-angular.md)): its `validate()` (`ts` entry points, _`D444`_; options `typeCheck` and `zone`, _`D443`_, _`D445`_) and host check (Angular 20 and later, _`D442`_, found from the documentation file's folder as _`D344`_ (PLAN-P7.2-react.md) does); loading the host's `@angular/compiler-cli`, its TypeScript and its Babel; compiling each showcase with `NgtscProgram` from memory, before Vite (_`D439`_, _`D448`_), the Angular Linker (_`D449`_), the production defines; the mount module (`createApplication()`, `createComponent()`, zoneless or zone, _`D440`_, _`D443`_); the default export check (_`D440`_); type checking, Angular's own, with its errors at their lines (_`D445`_), and the `ts` showcase adapter's own type check left out; the files the compiler reads, for `serve`'s watcher; fixtures on Angular 22 from this repository and installed fixtures on 20 and 21 (_`D450`_, _`D451`_); unit, `integration`, `e2e` and `serve` tests; `README.md`, `AGENTS.md`, `CONTRIBUTE.md`.
- **_`P11.2`_ The `angular` showcase adapter example** (draft; to be planned in its own file, settling the example's content then, as _`D350`_ (PLAN-P7.2-react.md) did for `react`: the mock project, and whether it shows a `templateUrl`/`styleUrl`, the `zone` option or an NgModule import): `examples/angular/README.md`, a mock project on the examples' theme (_`D312`_, SPEC.md), its first showcase a linked showcase of a real file shown in `README.md` too (_`D315`_, SPEC.md), with a `tsconfig.json` of its own (_`D307`_, SPEC.md); `README.md`'s `angular` part linking to its showcases (_`D309`_, SPEC.md); this repository's own `check --showcases` building it.

## Decisions

- _`D447`_ (`live`): **Two child segments: _`P11.1`_ the `angular` showcase adapter, then _`P11.2`_ its example**, each planned, approved, implemented and checkpointed on its own, each with a check in the browser (option chosen: "P11.1 + P11.2 (Rec.)"). Rejected: one segment (a larger change to review at once); three, with type checking apart (it comes from the same compiler call).
- _`D448`_ (`live`, changed by _`D458`_ (PLAN-P11.1-angular.md); refines _`D255`_ (PLAN-P7.1-ts.md) for `angular`): **One Angular compile per showcase**, inside that showcase's own Vite build, one after another, as _`D255`_ builds `ts` showcases; no measurement and no criterion (the user: "I don't care about build performance too much at this point, I prefer simplicity and stability where we can get it"; option chosen: "Per showcase (Rec.)"). Sharing the work later (one `NgtscProgram` per run and nearest tsconfig, its errors filtered per showcase by the files it reaches, and a cache of linked modules) changes only the `angular` showcase adapter's internals, not the format, the interface or the tests' expectations. Rejected: sharing from the start (more to build and test now, for speed not asked for).
- _`D449`_ (`live`): **The Angular Linker runs on every JavaScript module a build loads that needs it** (Angular's `needsLinking()`, a check of the module's content), not only under `node_modules`, so the host's own Angular library, built partially compiled (e.g. by ng-packagr into `dist/`) and imported by its package name (_`D236`_, SPEC-S6-showcases.md), works; a fixture with a committed, partially compiled library covers it (option chosen: "Every JS module (Rec.)"). Rejected: `node_modules` only, as in the spike (the host's own built library fails at run time).
- _`D450`_ (`live`, refined by _`D452`_; refines _`D245`_ (PLAN-P7-ts-react.md)): **Every supported major of a framework is tested**: the current major comes from this repository's own install (bumped by Dependabot), and each older supported major is an installed fixture (a committed lockfile, `installFixture()`, built in `integration` and `e2e`, as _`D349`_ (PLAN-P7.2-react.md) installs React 18). When this repository moves to a new major, the major it replaces gets an installed fixture in the same change; a major dropped from support (its specification decision changed) loses its fixture. For Angular (_`D442`_, SPEC-S6-showcases.md): 22 from this repository (_`D451`_), 20 and 21 installed; for React (_`D237`_, SPEC-S6-showcases.md), as today: 19 from this repository, 18 installed (`showcase-react-18`). Recorded as a gotcha in `AGENTS.md`, generalising today's React-only one ("Fixtures on another React than `showroom`'s own…") in _`P11.1`_'s documentation work (the user: "with our eye on supporting all upcoming major versions going forward"; option chosen: "Policy, 20+21 installed (Rec.)"). Rejected: only 20 installed (21 untested); every major installed, the current one too (one more fixture to keep current by hand).
- _`D451`_ (`live`, refined by _`D452`_; refines _`D307`_ (SPEC.md)): **New devDependencies: `@angular/core`, `@angular/common`, `@angular/compiler`, `@angular/compiler-cli`, `@angular/platform-browser` (`^22`), `rxjs` (`^7`, Angular's peer dependency) and `zone.js`**, for the fixtures on the current Angular (_`D450`_), the `zone` option (_`D443`_, SPEC-S6-showcases.md) on 22 too, and the example (_`D307`_); `tslib` is already installed. Dependabot's grouped devDependency updates bump them, majors included (option chosen: "Add, with zone.js"). Rejected: without `zone.js` (the `zone` option tested only on the installed fixtures); no new devDependencies (every Angular fixture installed, and the example needing an install of its own, against _`D307`_).
- _`D452`_ (`live`; refines _`D450`_, _`D451`_; from review 2026-11-14 #1; resolves _`O79`_): **A unit test guards the supported majors**: it reads the installed majors of `react`, `@angular/core` and `typescript`, and fails when they don't match a declared list of current majors, when an older supported major (_`D450`_) has no installed fixture, or when `typescript` leaves the range `@angular/compiler-cli` accepts; its message says what to do (e.g. "Angular 23 installed: add the `showcase-angular-22` fixture, and update the current majors"). Dependabot keeps proposing majors, as prompts to reconsider versions, in groups of their own (React, Angular with `rxjs` and `zone.js`, TypeScript), so a failing major never blocks the other updates; patch and minor updates flow as today, checked by CI. Built in _`P11.1`_, React's guard included; `AGENTS.md` records it. The guard against a stray merge stays a repository setting (branch protection with required checks and review, `AGENTS.md` › Continuous integration). The user's idea, critiqued (the user: "I want to propose a system (tests) for which versions we have accepted, so that a stray direct merge can't happen … JUST AN IDEA - please critique it"; option chosen: "Targeted majors guard (Rec.)"). Rejected: every package's exact version in an accepted list, failing every Dependabot pull request until updated (duplicates the lockfile, red by design hides real failures, weekly upkeep, and doesn't block a merge); Dependabot ignoring Angular majors (the user's first answer, "Ignore majors + open pt", replaced: no pull request would prompt the bump).
