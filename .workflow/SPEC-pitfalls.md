# Pitfalls

Pitfalls of the specification (`./.workflow/SPEC.md`), tagged _`K…`_: risks that could make us backtrack or stall later, each with what resolved it, once resolved.

- [x] _`K1`_ **Showcases need the host's own code and framework.** A showcase imports host code, so it has to be bundled with the host's own React (two copies of React break hooks), its tsconfig and its dependencies. A showcase application built once and shipped prebuilt can't do this. Why it matters: if the first version's architecture assumes no bundler, showcases could force a rewrite. Resolved by _`D2`_: the showcase application is built with Vite against the host repository from the start. Making the host's own dependencies resolve correctly is still part of _`K7`_.
- [ ] _`K2`_ (taken by _`P1`_) **Other frameworks inside a React/FluentUI SPA.** An Angular (or other) component can't be rendered as a React component. Showcases for those frameworks would need iframes or web components. Why it matters: this shapes the stack adapter interface, even though it only bites later.
- [x] _`K3`_ (taken by _`P3`_) **Hosts that don't use Node.** `../dotnetschema` has no `package.json`. The tool still needs Node to run (e.g. through `npx`), and its project information would come from `.slnx`/`.csproj`. Why it matters: "included into the host repository" means something different there. Resolved by _`P3`_'s _`D69`_: run through `npx --package`, documented; such hosts still need a stack adapter of their own (later).
- [x] _`K4`_ (taken by _`P2`_, _`P3`_) **Static hosting under a subpath.** GitHub Pages serves a site under `/<repo>/` and doesn't rewrite paths on the server. The SPA needs relative asset paths, and hash routing (or a `404.html` fallback). Why it matters: deep links break otherwise. Hash routing resolved by _`P2`_ (_`D37`_); relative asset paths by _`P2.2`_'s Vite configuration (`base: './'`), reused by _`P3`_'s build (_`D66`_).
- [x] _`K5`_ (taken by _`P2`_) **Links inside Markdown.** Relative links in a README (to other docs, source files or `LICENSE`) must be rewritten to SPA routes or repository URLs. Why it matters: otherwise they break in the showcase application. Resolved by _`P2`_'s _`D38`_: links to documentation files become routes; any other relative link is shown as plain text (no repository URLs, which are the SCM adapters' job).
- [x] _`K6`_ **The example hosts aren't React projects.** `../tsstd` and `../tsschema` are plain TypeScript libraries, and `../dotnetschema` is .NET. Why it matters: a React-only first adapter might not cover any of the example hosts. Resolved by _`D1`_: the first stack adapter is a TypeScript one.
- [ ] _`K7`_ (taken by _`P2`_, _`P3`_) **Where the showcase application's own dependencies come from (_`D2`_).** Building with Vite needs Vite, React and FluentUI. If they're tsshowcase `dependencies`, every host repository installs them, including hosts without React (`../tsstd`) and without Node (`../dotnetschema`, through `npx`). If the host repository is asked to install them, it carries that setup. Later, showcases must use the host's own React and not a second copy. Why it matters: it decides how heavy and fragile installing and running `tsshowcase build` is. Resolved for the showcase application by _`P2`_ (_`D48`_, _`D57`_: tsshowcase's own `dependencies`, aliased so a host's React never mixes in); using the host's own React remains open for showcases.
- [x] _`K8`_ **"`README` anywhere" needs exclusions (_`D6`_).** Taken literally, it includes every README in `node_modules/`, `dist/` and other generated folders. Why it matters: the showcase application would fill up with third-party docs. Resolved by _`D10`_: the stack adapter lists what to skip, and the configuration can override it.
