## Goals

_`S12`_'s showcase views (SPEC-S12-showcase-views.md): _`D495`_–_`D502`_, _`D508`_'s default views, _`D509`_'s layout (_`D546`_ (PLAN-P15-showcase-views.md)), _`D519`_, _`D520`_, _`D523`_'s `showcaseViews` name, custom default and 8 lines, _`D526`_'s `check` error, _`D530`_'s clearing of the `console` view, _`D534`_, _`D540`_, and _`D538`_'s parts on _`D96`_'s default views and _`D354`_. Not in _`P15.4`_: the status marks, the issue list and the issues' markers (_`P15.5`_); `serve`'s error frame stays until _`P15.5`_, and a block with no visible showcase frame shows its issues only in the terminal and the issues bar (_`D547`_ (PLAN-P15-showcase-views.md)); _`D529`_'s "not built" placeholder (_`P15.5`_, _`D580`_); `include=source` and `include=markdown`, and the Markdown tab still only with `exposeShowcaseMarkdownSyntax` (_`P15.6`_); `view=` on a linked showcase shown inline (_`P16`_, _`D526`_, _`D514`_).

Facts found while planning (2026-11-15):

- The marker's keys are parsed by `parseShowcaseMarker()` (`src/markdown/`, `_MARKER_KEYS`: `file`, `anchor`, `inline`, `block`, `include`), and where each may be used is checked by `scanMarkdown()`.
- `getShownHostInformation()` (`src/vite/`) ships only the showcases with a built showcase frame, each with its tabs and its frame's URL; a showcase's Markdown source (`getShowcaseSources()`) is read only with `exposeShowcaseMarkdownSyntax`.
- A virtual file with no showcase adapter isn't in the shown host information: `react-markdown` renders its fence as an ordinary code block.
- `ShowcaseBlock` (`src/app/code-pane/`) is a grid of the showcase frame (at least 64 px, _`D437`_ (PLAN-P10.5-console.md)) and the code pane, the cycling button floating over the showcase frame's top-right corner while the code pane is hidden (_`D407`_, _`D414`_ (PLAN-P10.4-code-pane.md)).
- `ts` showcases that render into the page (`examples/ts/`: the countdown, `list.ts`; some of `README.md`'s) would show as `source,console` under the new `ts` default.

## Decisions

The draft's choices 1–14 (`./.workflow/.temp/questions-p15.4/QUESTIONS.md`): options chosen "Agreed" for 1, 3, 5–8, 10–14; Q2, Q4 and Q9 discussed (below).

- _`D569`_ (`live`; refines _`D548`_ (PLAN-P15-showcase-views.md); Q1, "Agreed"): **_`P15.4`_ is not split further**: one segment, in the steps below, as the data half alone would change nothing a browser can check. Rejected: two children (the views in the data; the showroom).
- _`D570`_ (`live`; refines _`D500`_ (SPEC-S12-showcase-views.md); resolves _`O81`_ (SPEC-S12-showcase-views.md), _`K21`_ (SPEC-pitfalls.md); Q2, the user: "Did the spike find `display: none` does not work?", then option chosen: "opacity: 0, clipped (Rec.)"): **A `console` view with no `demo` view holds the showcase frame hidden**: at the views' width and its own reported height, `opacity: 0`, `pointer-events: none`, `aria-hidden`, `tabindex="-1"`, inside a 0-high `overflow: hidden` box at the top of the `console` view. The user checks Firefox and Safari at the checkpoint (the spike's gap). Rejected: `display: none` (scripts run, but the page has no layout: sizes and the viewport read 0, media queries answer as for a 0-wide viewport, CSS animations never run); off-screen positioning.
  - Evidence: Spike 2026-11-15 (`./.workflow/.temp/spike-hidden-frame/`, Chromium 158, seven same-origin frames measured for 3 s): no hiding throttled timers, animation frames or timeouts (296–297 10 ms intervals, 181–182 frames, timeouts 6–8 ms late in every case); `display: none` gave a 0 × 0 viewport and box, no CSS animation iterations and a failed `min-width: 400px`; a 1 × 1 px frame a 1 × 1 viewport and a failed media query; `opacity: 0` at the real size in a 0-high `overflow: hidden` box matched the visible frame in every measure but the IntersectionObserver (not intersecting), as a visible frame below the fold also reports. `document.visibilityState` was `visible` throughout. Not run: Firefox (known to stop animation frames in `display: none` frames) and WebKit; a background tab throttles every frame alike.
- _`D571`_ (`live`; refines _`D501`_, _`D508`_, _`D523`_ (SPEC-S12-showcase-views.md); Q3, "Agreed"): **A showcase adapter declares its default views as an optional property, `defaultViews?: readonly ShowcaseView[]`**, with a new exported type `ShowcaseView` (`'markdown' | 'source' | 'demo' | 'console' | 'none'`). A custom showcase adapter without it gets `['demo']`; an invalid one (empty, repeated, unknown, `none` with another view) is an error when the custom showcase adapter is loaded. Built-ins: `html`, `react` and `angular` `['demo']`, `ts` `['source', 'console']`. Rejected: a method `getDefaultViews()` (per showcase is what `view=` is for).
- _`D572`_ (`live`; refines _`D495`_, _`D519`_, _`D526`_ (SPEC-S12-showcase-views.md); Q4, the user: "I want to reexamine why inline showcases would only ever be `view=demo`?", then option chosen: "Keep D526 until P16 (Rec.)"): **Where the views live**: `Showcase.views: ShowcaseView[]`, required, resolved by `check()` through the layers (the showcase adapter's default, `showcaseViews`, `view=`); a linked showcase shown inline is always `['demo']`, `view=` on it a `check` error, until _`P16`_ makes it a link opening the sidebar, where `view=` takes any views with no defaults (_`D514`_); `VirtualFile.views?`, set only on a virtual file with no showcase adapter (`['source']` unless its marker says `markdown` or `none`). `scanMarkdown()` parses and checks `view=` and where it may be used; `check()` applies the defaults. Rejected: `view=` on an inline link drawn before its paragraph now (replaced by _`P16`_); the defaults applied in the showroom (a custom showcase adapter couldn't see its showcase's views).
- _`D573`_ (`live`; refines _`D502`_ (SPEC-S12-showcase-views.md); Q5, "Agreed"): **`showcaseViews` maps a showcase adapter's name to a view or an array of views** (`"ts": "source"`, `"ts": ["source", "console"]`), each validated as `view=` is by `validateConfiguration()`; a name that is neither a built-in showcase adapter's nor in `customShowcaseAdapters` is reported by `check()`, as an error. Rejected: a string in `view=`'s grammar (`"source,console"`).
- _`D574`_ (`live`; refines _`D500`_ (SPEC-S12-showcase-views.md); Q6, "Agreed"): **A showcase frame nothing loads is never shipped**: a showcase with neither a `demo` nor a `console` view is built and checked as any other, but `build` doesn't emit its showcase frame, and its shown showcase has no `url`; `serve` serves what it built, but the showroom never loads it. Rejected: emitting every showcase frame (pages no one can reach).
- _`D575`_ (`live`; refines _`D509`_ (SPEC-S12-showcase-views.md), _`D546`_ (PLAN-P15-showcase-views.md); changes _`D407`_, _`D414`_ (PLAN-P10.4-code-pane.md); Q7, "Agreed"): **The block's header bar, before _`P15.5`_**: a 32 px bar across the top of the block, the cycling button at its right end, its left empty until _`P15.5`_'s status marks; the views stacked under it in their order, each separated by a thin divider; at half, the code pane beside the whole stack, or below it where the block is narrow. ## Steps

1. **The views in the host information** (`src/host/`, `src/markdown/`, `src/configuration/`, `src/adapters/showcase/`, `src/cli/check/`): `ShowcaseView`; `view=` in `parseShowcaseMarker()` (a view or a comma-separated list, case-sensitive; repeated, empty, unknown and `none` with another view are errors) and in `scanMarkdown()` (an error on an inline link, _`D526`_; `demo`, `console` and `include=` on a virtual file with no showcase adapter, and `view=none` with `include=`, are errors, _`D519`_, _`D534`_); `Showcase.views`, `VirtualFile.views` (_`D572`_); `showcaseViews` (_`D573`_); `defaultViews` on the built-in showcase adapters and on loaded custom ones (_`D571`_); `check()` resolving the layers. Tests: `src/markdown/` (the grammar and where it's used), `src/configuration/` (`showcaseViews`), `src/adapters/showcase/registry/` (defaults, invalid custom defaults), `src/cli/check/` on the new `showcase-views` fixture (the layers, every error), the existing fixtures' expected showcases gaining `views`.
2. **The shown host information** (`src/vite/`, `src/app/host/`, `src/cli/build/`, `src/cli/serve/`): `ShownShowcase`'s `views`, `markdown` and optional `url` (_`D574`_, _`D578`_); the shown virtual files with no showcase adapter whose views aren't `source`; `build` emitting only showcase frames a view loads; `serve`'s events and `getShownChange()` with the new fields. Tests: `src/vite/`, `src/app/host/`, `src/cli/serve/` unit tests; `build()`'s `e2e` (a `source`-only showcase's frame not emitted), the `serve` tier.
3. **The block and its header bar** (`src/app/code-pane/`, `src/app/showcases/`, `src/app/console/`): the header bar with the cycling button (_`D575`_); the views stacked under it; the code pane beside or below the stack; the `demo` view's 32 px minimum and the open console panel's room dropped (_`D576`_); the remark plugin placing a block for every shown showcase, removing a `view=none` one's entry point, and placing the shown virtual files with no showcase adapter. Tests: `ShowcaseBlock` rendered on the server in each state (the header bar, the button's place, the order of views, the code pane beside the stack), the remark plugin's placements.
4. **The views** (`src/app/showcases/`, `src/app/code/`, `src/app/console/`, `src/app/code-sidebar/`): `source` and `markdown` (_`D577`_, _`D578`_: the two highlights, one line numbering, the height), `demo` (the overlay only without `console`), `console` (_`D579`_: 8 lines, following the newest line, "No output", cleared on `start`), the hidden showcase frame (_`D570`_). Tests: each view rendered on the server (the highlights' segments and line count, the not-text and missing messages, the placeholder, the overlay present or not, the hidden frame's attributes and styles), the following decision as a pure function.
5. **Examples and `README.md`** (_`D581`_): `view=` on the rendering `ts` showcases of `README.md` and `examples/ts/`; the cheat-sheet's `view=` and `showcaseViews`; a "Showcase views" section with a live showcase of each view; `ShowcaseView`, `Showcase.views`, `VirtualFile.views`, `ShowcaseAdapter.defaultViews` and `showcaseViews` in `# Usage` (the `ts` blocks checked with `tsc`); the `ts` example's text where it names what shows.
6. **Documentation**: `AGENTS.md` (Exports, Testing: the `showcase-views` fixture and the views' tests; the gotchas on the block's layout, the hidden showcase frame and frames nothing loads), `CONTRIBUTE.md` (the architecture; the Glossary as _`D582`_ says); the plan decisions this changes marked (_`O84`_): _`D407`_, _`D414`_ (PLAN-P10.4-code-pane.md), _`D437`_ (PLAN-P10.5-console.md), _`D564`_ (PLAN-P15.3-console.md); _`O81`_ and _`K21`_ ticked off by _`D570`_.
7. **Green**: `npm run ci`; the dogfood `serve` started, and a scratch host in `./.workflow/.temp/p15.4-check/` (a copy, never a fixture) with every view and combination (`ts`, `react`, `html`, a custom showcase adapter's default, `showcaseViews`, `view=none`, virtual files with no showcase adapter in each view, a long entry point, a hidden showcase frame logging its sizes and media queries), for the user's check in a browser, in both themes, and in Firefox and Safari for the hidden showcase frame.
