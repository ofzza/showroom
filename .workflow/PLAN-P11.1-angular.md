# _`P11.1`_ The `angular` showcase adapter

approved 2026-11-14 (option chosen: "Approve and commit (Rec.)"), after two zero-context reviews; edited 2026-11-14 after its zero-context review, before approval (_`D453`_, _`D454`_, _`D456`_–_`D461`_, _`D463`_–_`D465`_ sharpened; _`D455`_ replaced by _`D466`_; _`D467`_ added; steps reordered); edited again after its second review (_`D454`_, _`D457`_–_`D460`_, _`D464`_, _`D465`_, _`D467`_)

## Goals

The `angular` built-in showcase adapter (_`S6.4`_ (SPEC-S6-showcases.md), _`D439`_–_`D446`_), as _`P11`_ (PLAN-P11-angular.md) scopes it: compiled by the host's own `@angular/compiler-cli` in memory, bundled through the `ts` showcase adapter's build (_`P7.1`_ (PLAN-P7.1-ts.md)), in `check --showcases`, `build` and `serve`; its fixtures on every supported Angular major (_`D450`_, _`D451`_), and the majors guard (_`D452`_, all PLAN-P11-angular.md). The example is _`P11.2`_'s.

## Decisions

Settled 2026-11-14 from _`P11`_'s open points (option chosen: "Accept all (Rec.)", for Q1–Q13 in one batch).

- _`D453`_ (`live`; Q1; refines _`D288`_ (PLAN-P7.1-ts.md) for `angular`; resolves _`O74`_ (PLAN-P11-angular.md)): **The program's roots are _`D288`_'s**: the nearest tsconfig's files (`files`, `include`, `exclude`) and the entry point, and the compiler emits all of them, once per compile (the spike's roots were the entry point only, its emit whole); errors are filtered to what the showcase reaches (_`D289`_ (PLAN-P7.1-ts.md), _`D457`_). A large host's whole project is analysed and emitted for every showcase (_`D448`_ (PLAN-P11-angular.md)), accepted for simplicity. Rejected: emitting only the files Vite loads (Angular's `prepareEmit()` transformers and TypeScript's per-file `emit()`, as the Angular CLI does; faster, unproven here); the entry point and the tsconfig's declaration files only (not the host's whole view, _`D445`_ (SPEC-S6-showcases.md)).
- _`D454`_ (`live`; Q2; refines _`D440`_ (SPEC-S6-showcases.md); resolves _`O70`_'s default export part (PLAN-P11-angular.md)): **The default export check is made at build time, on the compiled program**, whatever `typeCheck` says: TypeScript's checker resolves the entry point module's `default` export, through re-exports and aliases, to its declaration, which must be a class with an `@Component` decorator (the decorator's identifier resolved through the checker to `@angular/core`'s `Component`, so aliased imports work) whose argument doesn't set `standalone: false`; otherwise the build fails at the entry point's line, `NG`-free (e.g. "The default export of an angular showcase must be a standalone component"). A module without a default export is left to the bundle, which fails it as for `react` (the check skips that case, so it is reported once). The mount module checks again at run time (`reflectComponentType()`), as a fallback, in the console panel. Rejected: at run time only (_`D343`_ (PLAN-P7.2-react.md)'s route for React; would change _`D440`_); the entry point's syntax only (`export default class`; re-exports fail wrongly).
- _`D455`_ (replaced by _`D466`_; Q3; resolves _`O78`_ (PLAN-P11-angular.md)): **An `angular` showcase frame is the `ts` page** (as _`D342`_ (PLAN-P7.2-react.md)), its console panel showing Angular's warnings and errors; **the mount module drops exactly Angular's "Angular is running in development mode." line**, wrapping `console.log` only while it creates the application, so the panel doesn't open on every showcase in `serve`. Rejected: accepting it; a filter list in the shared console script (self-contained, and shared by every showcase adapter).
- _`D456`_ (`live`; Q4; resolves _`O71`_'s TypeScript part (PLAN-P11-angular.md)): **TypeScript 7 is `check`'s, the range is Angular's own check**: `check()` and `build()` judge the `typescript` that `@angular/compiler-cli` resolves (_`D463`_) with `judgeTypeScriptVersion()` (`ts/typecheck/`), reporting TypeScript 7 (_`K16`_ (SPEC-pitfalls.md)) as an error for `angular` showcases, as _`D442`_ (SPEC-S6-showcases.md) requires, where `ts` only warns (_`D274`_ (PLAN-P7.1-ts.md)); a 5.x or 6.x outside `@angular/compiler-cli`'s range is Angular's own check (its `NgtscProgram` throws), reported as a build error at the showcase (in `check --showcases`, `build`, and the frame in `serve`). No semver parser in `showroom`'s own code (review 2026-11-14 #1). Rejected: parsing `@angular/compiler-cli`'s `peerDependencies.typescript` in `check`.
- _`D457`_ (`live`; Q5; refines _`D289`_ (PLAN-P7.1-ts.md); resolves _`O70`_'s diagnostics part (PLAN-P11-angular.md)): **Diagnostics**: TypeScript's as today (`TS<code>: <message>`, `mapDiagnostic()`, at their file and line, virtual files by their paths); Angular's own (codes `-99<code>`) as `NG<code>: <message>`, as `ng build` shows them, through the same mapping; a template diagnostic is at its line in the inline `template` (in the `.ts` file) or in the `templateUrl` file, real or virtual. _`D289`_'s filter applies to every diagnostic bound to a file (syntax, structural, semantic and template diagnostics, collected per reached file, e.g. `getNgSemanticDiagnostics(file)`), a reached component's template and style files counting as reached with it, so an error in a file no showcase reaches never fails one; diagnostics without a file (options, global) always apply. Syntax, option and structural errors fail the build whatever `typeCheck` says; type errors (TypeScript's semantic and Angular's template diagnostics) only unless it is `false` (review 2026-11-14 #7). Warning-category diagnostics in reached files (Angular's extended diagnostics, e.g. `NG8107`, as the host's `angularCompilerOptions` set them) become the showcase's build warnings, as `ng build` shows them, unless `typeCheck` is `false` (review 2026-11-14 (2nd) #9, option chosen: "Show as warnings (Rec.)").
- _`D458`_ (`live`; Q6; resolves _`O73`_ (PLAN-P11-angular.md); changes _`D439`_ (SPEC-S6-showcases.md) and _`D448`_ (PLAN-P11-angular.md): the compiler runs before Vite, not inside a Vite plugin or the Vite build): **The adapter compiles first, then calls `buildTsShowcase()`**: Angular's program runs in memory before Vite (not in a plugin's `buildStart`), giving the emitted JavaScript and source maps, the diagnostics and the files read; `buildTsShowcase()` gains two optional fields, extra `plugins` (loading the emitted JavaScript for the compiled files; the Linker, _`D449`_ (PLAN-P11-angular.md)) and `typeCheck: false`, overriding its own type check (_`D445`_ (SPEC-S6-showcases.md)), and the compile's reads join the build's; when the compile has errors that always fail (syntax, options, structural, the default export check of _`D454`_), or emitted nothing for the entry point, they are returned and Vite isn't run (it would otherwise transform the raw TypeScript); otherwise Vite runs, and a bundle that fails returns its errors alone, else the compile's type errors (unlike `ts`, which only type checks after a successful bundle, the compile's type errors are known before it). `buildTsShowcase()` also gets the set of compiled module ids (_`D460`_). The extra `plugins` go after the reads plugin (which must still see every module) and before the virtual files plugin (which would return a virtual entry point's raw TypeScript); the loading plugin returns the emitted code with `moduleType: 'js'` and its source map. `ts` and `react` behave exactly as before (review 2026-11-14 #4, #6). Rejected: compiling in a plugin's `buildStart` (its errors would come back as one thrown error through `getBuildErrors()`).
- _`D459`_ (`live`; Q7; resolves _`O72`_ (PLAN-P11-angular.md)): **Only what emitting in memory needs is overridden**: `noEmit` and `noEmitOnError` off, `declaration` and `emitDeclarationOnly` off, _`D234`_'s dropped options (`DROPPED_COMPILER_OPTIONS`: `outDir`, `rootDir`, `composite`, `sourceMap`, …), then `sourceMap` and `inlineSources` set again (_`D460`_), and `suppressOutputPathCheck` (without `outDir`, a host with `allowJs` would otherwise fail with TS5055, "would overwrite input file"; output paths stay beside the sources, so the maps' relative `sources` hold) (review 2026-11-14 #3); in `angularCompilerOptions`, `compilationMode: 'full'` forced, `flatModuleOutFile`, `flatModuleId` and `tracePerformance` dropped. `module`, `target` and every other option stay the host's (Rolldown bundles CommonJS output too).
- _`D460`_ (`live`; Q8; refines _`D263`_ (PLAN-P7.1-ts.md); resolves _`O76`_ (PLAN-P11-angular.md); changed after review 2026-11-14 (2nd) #4, option chosen: "No line mapping"): **Source maps, and no line mapping**: `sourceMap` and `inlineSources` on, each `.js.map` captured in the compiler host's `writeFile` and the `sourceMappingURL` comment stripped, handed to Vite with the emitted code, so `serve`'s showcase frames map to the `.ts` files, with their content, in the browser's developer tools. A bundler error located in a compiled module (by `loc` or `pos`, which point into the emitted JavaScript) is placed at that file without a line, as `_mapError()` would otherwise read the position against the `.ts` source; `buildTsShowcase()` is told which modules are compiled (_`D458`_). Such errors are rare: type checking reports most of them (e.g. a missing named export, TS2305) at their line first. The resolve plugin's unresolved imports already take their line from the original source (`_readSource()`), and stay as they are. Rejected: decoding the source maps to map positions (a hand-written decoder, or `@jridgewell/trace-mapping` as a new dependency).
- _`D461`_ (`live`; Q9; resolves _`O75`_ (PLAN-P11-angular.md)): **Warnings**: the Linker returns Babel's source map; a bundler warning about Angular's own packages that the fixtures show is silenced by its code together with its module's id under `node_modules/@angular/` (a new list beside `SILENCED_WARNINGS`, `src/cli/check/internal/`, whose code-only entries would also hide the host's own), so the host's warnings still show (_`D270`_ (PLAN-P7.1-ts.md)) (review 2026-11-14 #8); a test asserts a clean `showcase-angular` build has no warnings, in both modes.
- _`D462`_ (`live`; Q10; resolves _`O68`_ (PLAN-P11-angular.md)): **What `serve` watches, and the modes**: the compile's reads are the program's source files and the resource files the compiler read (templates, styles), outside `node_modules`, virtual files as their documentation files, and the tsconfig files (as _`D285`_ (PLAN-P7.1-ts.md)), kept while a build fails (_`D272`_ (PLAN-P7.1-ts.md)); `production` defines `ngDevMode`, `ngJitMode`, `ngI18nClosureMode`, `ngServerMode` and `ngHmrMode` as `false`, `development` defines none, from the request's mode, never `process.env.NODE_ENV` (_`D261`_ (PLAN-P7.1-ts.md)).
- _`D463`_ (`live`; Q11; resolves _`O71`_ (PLAN-P11-angular.md), with _`D456`_): **Loading, and the host check**: found from the documentation file's folder as Node does (as _`D344`_ (PLAN-P7.2-react.md)): `@angular/core`, `@angular/common`, `@angular/compiler`, `@angular/compiler-cli` and `@angular/platform-browser`, each 20.0.0 or later, all of one major; `typescript` resolved from `@angular/compiler-cli`'s own folder (the one it imports itself), and used for the compiler host and the checker too, so one TypeScript instance serves both (review 2026-11-14 #2), judged as _`D456`_ says; `zone.js` only for the showcases with `zone: true` (_`D443`_ (SPEC-S6-showcases.md)). The compiler (its ES module bundle), its TypeScript, the Linker and its Babel (resolved from `@angular/compiler-cli`'s own folder, as Node ignores `import.meta.resolve()`'s parent) are loaded with `import()` inside `build()` only, so `check` without `--showcases` and library users never load them; `build()` finds them again (as _`D297`_ (PLAN-P7.1-ts.md)), failing the showcase when they are gone; Node keeps them for the process, so `README.md` says to restart `serve` after upgrading Angular (as _`D295`_ (PLAN-P7.1-ts.md)).
- _`D464`_ (`live`; Q12; resolves _`O69`_, _`O77`_ (PLAN-P11-angular.md)): **Fixtures**: `showcase-angular` (Angular 22, this repository's): inline and linked entry points, a virtual and a real `templateUrl` and `styleUrl`, a host component and root service, signal inputs and an output, an NgModule import (`CommonModule`), the host's own partially compiled library by its name (a committed `lib/` with its declarations (`.d.ts`, for the template type check of its components), generated once by a script in the fixture with this repository's `@angular/compiler-cli` in `compilationMode: 'partial'`, _`D449`_ (PLAN-P11-angular.md)), the `zone` option; built in both modes. `showcase-angular-errors`: a missing default export, a default export that isn't a standalone component, a type error in TypeScript, in an inline template and in a `templateUrl` file, an extended diagnostic (a warning), and `typeCheck: false` (with a missing named export, the bundle's error placed at its file without a line, _`D460`_). `showcase-angular-20` and `showcase-angular-21`, installed (`INSTALLED_FIXTURES`): their own `typescript`, `tslib`, `rxjs` and `zone.js` locked, `types: []`, installed with `--ignore-scripts`; a test that each resolves its own TypeScript; built in `integration` and `e2e`. `serve` serves `showcase-angular`. A solution-style tsconfig (`files: []`, `references`, as the Angular CLI generates) in one folder of `showcase-angular` (_`D467`_), and a host component with an error that no showcase reaches (_`D457`_). The extra CI time is accepted: two installs in every CI job, as `npm ci` wipes `node_modules/.cache/` (cached per lockfile only locally) (review 2026-11-14 #14).
- _`D465`_ (`live`; Q13; for _`D452`_ (PLAN-P11-angular.md)): **The majors guard** is a unit test of `src/testing/`, beside `INSTALLED_FIXTURES`: `CURRENT_MAJORS` (`react` 19, `@angular/core` 22) matching this repository's installed majors; the supported floors (`react` 18, Angular 20) taken from the adapters' own constants (`MINIMUM_REACT_VERSION`, and the `angular` adapter's), each older supported major's installed fixture present; and this repository's `typescript` inside `@angular/compiler-cli`'s `peerDependencies.typescript` range (a small parser in the test helpers, never in `showroom`'s own code). `.github/dependabot.yml` gets three groups, listed before `dev-dependencies` (Dependabot puts an update in the first group that matches): `react` (`react`, `react-dom`, `@types/react`, `@types/react-dom`) and `angular` (`@angular/*`, `rxjs`, `zone.js`) with `update-types: ['major']`, so their minor and patch updates stay where they are today (_`D452`_ (PLAN-P11-angular.md)): the shared devDependencies pull request, except `react` and `react-dom`, production dependencies (the showroom's own), which Dependabot proposes one pull request each, as today (a React major also changes the showroom itself, `getReactAliases()`) (review 2026-11-14 (2nd) #5, option chosen: "State it, no new group (Rec.)"), and `typescript` with every update type, as a minor update can leave `@angular/compiler-cli`'s range (`>=6.0 <6.1` on 22); `typescript`'s current major (6) joins `CURRENT_MAJORS` (review 2026-11-14 #12).
- _`D466`_ (`live`; replaces _`D455`_, carrying its resolution of _`O78`_ (PLAN-P11-angular.md); from review 2026-11-14 #9, option chosen: "attachView, drop D455's wrap (Rec.)"): **The mount module creates the application, the component, and attaches its view**: `createApplication()` with the zoneless or zone provider (_`D443`_ (SPEC-S6-showcases.md)), `createComponent()` in the showcase frame root with the application's injector, then `attachView(ref.hostView)`, without which the view never refreshes (as the spike did). An `angular` showcase frame is the `ts` page (as _`D342`_ (PLAN-P7.2-react.md)), its console panel showing Angular's warnings and errors; Angular's "Angular is running in development mode." is only logged by `bootstrap()`, which isn't used, so nothing is filtered; the browser check confirms the panel stays quiet in `serve`. Rejected: `bootstrap()` with _`D455`_'s `console.log` wrapper (the usual path, but needs the filter).
- _`D467`_ (`live`; refines _`D445`_ (SPEC-S6-showcases.md); from review 2026-11-14 #10): **Reading the tsconfig**: the nearest one (`findTsConfig()`, from the documentation file's folder up) is parsed as `getTypeCheckConfiguration()` parses it (`readJsonConfigFile()`, `parseJsonSourceFileConfigFileContent()`, so its errors have their line and its extended files are known), for the compiler options, the roots, the errors and the tsconfig files; only the merged `angularCompilerOptions` (`extends` followed) come from Angular's `readConfiguration()`, whose own errors carry no position (review 2026-11-14 (2nd) #1): its `options` are TypeScript's merged with `angularCompilerOptions` (`Object.assign`), so the options used are `readConfiguration()`'s, overlaid with the source file parse's, then _`D459`_'s overrides (checked against `@angular/compiler-cli` 22.2's `readConfiguration()`, 2026-11-14); TS18002 and TS18003 ("No inputs were found") are dropped as `ts` drops them (a solution-style tsconfig, `files: []` with `references`, as the Angular CLI generates, then has only the entry point as a root, as for `ts`); its other errors are reported at the tsconfig (_`D291`_ (PLAN-P7.1-ts.md)); its extended files are among the reads (_`D462`_). Without a tsconfig, TypeScript's defaults and Angular's apply, the entry point the only root, as for `ts` (_`D234`_ (SPEC-S6-showcases.md)).

## Steps

1. **Dependencies** (`package.json`, `package-lock.json`): the devDependencies of _`D451`_ (PLAN-P11-angular.md), installed with `npm install --save-dev` (the network; no install scripts of their own); `.github/dependabot.yml`'s groups (_`D465`_).
2. **Fixtures and installs** (`test/fixtures/showcase-angular*/`, `src/testing/`, `src/testing/setup/`): _`D464`_'s fixtures, the committed partially compiled `lib/` and its script, the two installed fixtures' lockfiles in `INSTALLED_FIXTURES`; the majors guard (_`D465`_), broken deliberately once to see it fail; first, so each later step runs its affected tests.
3. **The shared build** (`src/adapters/showcase/ts/`): `buildTsShowcase()`'s `plugins` (placed as _`D458`_ says) and `typeCheck` fields; the set of compiled module ids, whose bundler errors are placed at their file without a line (_`D460`_); a test that Vite doesn't transform the emitted JavaScript again (its Oxc transform filters by id; if it does, the compiled ids are excluded through the `oxc` option); `validateTsShowcaseOptions()` taking the adapter's option names, so `angular` validates `typeCheck` and `zone` with the same messages; `ts` and `react` unchanged (their tests pass as they are); with its unit tests.
4. **The Angular compile** (a new `src/adapters/showcase/angular/`, never re-exported, a `compile/` folder if it grows): finding and loading the host's Angular and its TypeScript (_`D463`_, _`D456`_); the tsconfig (_`D467`_); the program with `ts/typecheck/`'s compiler host (virtual files from memory), _`D453`_'s roots and _`D459`_'s options, resource reads recorded through the compiler's `readResource` (template and style files only); a `SourceFileCache` per showcase only (_`D448`_ (PLAN-P11-angular.md)); diagnostics (_`D457`_); the default export check (_`D454`_); emitted code and source maps in memory (_`D460`_); reads (_`D462`_); with its unit tests (hand-made diagnostics, the options overridden, the default export check on `showcase-angular-errors`' files).
5. **The Vite plugins** (in `src/adapters/showcase/angular/`): loading the emitted JavaScript (_`D458`_, _`D460`_); the Linker on every module `needsLinking()` accepts (_`D449`_ (PLAN-P11-angular.md)), returning Babel's source map, and the Angular warnings' filter (_`D461`_); the production defines (_`D462`_); with unit tests of their hooks on a fake plugin context.
6. **The `angular` showcase adapter** (registered as `angular`, and removed from `PLANNED_SHOWCASE_ADAPTER_NAMES` (`src/adapters/showcase/registry/`), with its tests there updated): `validate()` (`ts` entry points, _`D444`_; options `typeCheck`, `zone`, _`D443`_, _`D445`_, all SPEC-S6-showcases.md); `check()` (_`D463`_, _`D456`_); the mount module (`<entry>.showroom-mount.js`, as `react`'s: `zone.js` first with `zone: true`, _`D466`_, the run-time check of _`D454`_); `build()` (_`D458`_); with unit tests (`validate()`, `check()` with injected resolvers and `package.json` files in scratch folders, the mount module's source).
7. **Integration, e2e and serve tests**: `integration` builds (_`D464`_; no warnings, _`D461`_; errors at their lines; the unreached error ignored; the solution-style tsconfig; Angular 20, 21 and 22; each installed fixture resolving its own TypeScript); `e2e`: `build()` on a copy of `showcase-angular` and of an installed fixture; `serve`: `showcase-angular` served.
8. **Documentation**: `README.md` (the `angular` showcase adapter: format, options, host requirements, TypeScript 7, zone and zoneless, the theme, restarting `serve` after upgrading Angular; the adapters table; the "planned" mentions removed (e.g. "(or a planned one's: `angular`)"); `# Development`: the installs needing the registry; any `showcase=angular` marker kept inside a fence until _`O80`_ (PLAN-P11-angular.md) settles `README.md`'s own; `ts` samples checked with `tsc` as `AGENTS.md` requires); `AGENTS.md` (Layout: `src/adapters/showcase/angular/`; Testing: the Angular tests and installs; Gotchas: the React-only installed fixtures gotcha generalised to every framework (_`D450`_ (PLAN-P11-angular.md)), the majors guard, the compiler loaded with `import()`, Angular's packages linked, one TypeScript instance, `suppressOutputPathCheck` among the compiler API's internals (the gotcha on missing public typings), the Angular warnings' list beside `SILENCED_WARNINGS` (that gotcha); Continuous integration: Dependabot's groups; Toolchain line: Angular 22); `CONTRIBUTE.md` (project structure; the Glossary's "Console panel": "a `ts`, `react` or `angular` showcase frame", the change proposed and accepted 2026-11-14, review 2026-11-14 (2nd) #11).
9. **Verification**: `npm run ci` green; a scratch host built and served with `showcase-angular`'s showcases, for the user's browser check (rendering, a signal input updating, the `zone` option, the theme, the console panel quiet in `serve`) at the checkpoint, before the example of _`P11.2`_.
