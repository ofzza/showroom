# _`P8`_ Showcase adapter examples

implemented 2026-11-13 (approved 2026-11-13)

## Goals

_`S8`_ (SPEC.md): a showcase adapter example for each existing showcase adapter, `html`, `ts` and a custom showcase adapter (_`D302`_, _`D304`_), each a mock project on the numbers-and-time theme (_`D312`_, _`D313`_), shown live in this repository's own showroom; and `README.md` restructured around them (_`D303`_, _`D305`_, _`D306`_, _`D309`_, _`D314`_, _`D315`_), before _`P7.2`_.

Not in _`P8`_: the `react` and `angular` examples (with their own segments, _`D304`_); checking heading fragments in `check` (_`S7`_'s "Ideas and later"); customizing the navigation (_`L13`_, PLAN.md).

Facts found while planning (2026-11-13):

- The showroom's heading ids come from `rehype-slug` (`github-slugger`), as GitHub's do, so `./examples/<adapter>/README.md#<id>` works in the showroom and on GitHub; the showroom's routes take the heading id (`#/<path>#<id>`, `formatRoute()`), so the live link is `https://ofzza.github.io/showroom/#/examples/<adapter>/README.md#<id>`, live from the release that reaches `master` (as _`D223`_ (PLAN.md)).
- `tsconfig.json` includes only `src/`, so `examples/` is never type checked by `tsc`, linted, built or published (`files: ["dist"]`); `ci:prettier` only looks at `src`.
- The `html` showcase adapter follows no real files: a showcase reaches only the resources of its documentation file's folder (README.md › Showcases). A linked `html` page in `examples/html/`, linked from the root `README.md`, gets the root folder's resources, not the example's.
- A `ts` showcase's type checking uses the tsconfig nearest the documentation file: the example's own one in its `README.md`, the root `tsconfig.json` for the same file linked from the root `README.md`.
- Examples inside this repository resolve this repository's TypeScript and `@types` (as fixtures do, AGENTS.md › Fixtures always resolve this repository's TypeScript and `@types`), so the `ts` example's tsconfig sets `types: []`.

## Decisions

- _`D316`_ (`live`; Q1, option chosen: "One segment"): **_`P8`_ is one segment**, implemented in one go, with one checkpoint, where the user looks at the examples in a served showroom. Rejected: three child segments, one per example (earlier content feedback, more stops).
- _`D317`_ (`live`; Q2, option chosen: "Integration test (Rec.)"): **An integration test guards `README.md`'s links into the examples**: in `src/cli/check/index.integration.test.ts`, every link in `README.md` into `examples/` with a `#<fragment>` must match a heading id of its target, as the showroom generates them (rendering the target with `src/app/markdown/`'s rendering, `rehype-slug` included, as its tests do, and collecting the ids; no new dependency). Rejected: checking heading fragments in `check` for every host (new scope, _`S7`_'s idea), and no guard.
- _`D318`_ (`live`, changed by _`D321`_; Q3, option chosen: "Same, in examples/number-table/"): **The custom showcase adapter example is `number-table`, in `examples/number-table/`**, named after the adapter itself: its module `examples/number-table/number-table.js` (plain JavaScript with JSDoc types, no imports), registered in `showroom.json` as `"customShowcaseAdapters": { "number-table": "./examples/number-table/number-table.js" }` (_`D308`_ (SPEC.md)). It builds a `json` code block or a linked `.json` file of numbers into a formatted table: options `{ columns, caption, locale }` checked in `validate()`, invalid JSON a build error at its line, a non-numeric cell a warning, its `reads`. Rejected: `examples/custom/`.
- _`D319`_ (`live`, changed by _`D322`_; Q4, option chosen: "Keep as they are (Rec.)"): **`README.md`'s own minimal demonstrations stay as they are** (_`D314`_ (SPEC.md)): the inline button (still the first showcase, `README.showcase-1.html`), the CSS resource, the linked button and the themed fragment; `examples/button.html` stays where it is, as `README.md`'s own file (so _`D309`_'s condition doesn't apply: the `html` example doesn't use it). `README.md`'s live `ts` block is replaced by the `ts` example's first showcase (_`D315`_ (SPEC.md)). Rejected: rethemeing them to numbers (cosmetic churn).
- _`D320`_ (`live`, changed by _`D321`_; changes _`D313`_ (SPEC.md); Q5, option chosen: "Go with these (Rec.)"): **The examples' contents**, adjustable at the checkpoint:
  - **`html`, `examples/html/`: "numerals", a mock CSS library.** Its stylesheet is a resource, `numerals.css` (`.grouped`, `.tabular`, `.comic`, `.lcd`), not a real file, as the `html` showcase adapter follows none (this changes _`D313`_ for `html`). First showcase, linked and shared with `README.md`: `examples/html/odometer.html`, a self-contained page (a 7-segment counter in CSS, with a small script, following the showroom's theme), as it must work from the root `README.md`'s folder too. Then showcases using the resource: tabular and proportional figures in a price table, colourful comic digits, a large figure in `light-dark()`.
  - **`ts`, `examples/ts/`: "tempo", a mock numbers and time library.** Real files `src/units.ts` (`enum Unit`), `src/duration.ts`, `src/relative.ts` (`Intl.RelativeTimeFormat`), `src/rounding.ts` (`Math`'s rounding pitfalls), and `tsconfig.json` (strict, `types: []`, its `include` covering the example). First showcase, linked and shared with `README.md`: `examples/ts/demo/countdown.ts`, a live countdown into `#root`, logging to the console panel. Then inline showcases: durations in the console panel, relative times, `0.1 + 0.2` and rounding, a `ts` resource two showcases share, and a `js` showcase importing the TypeScript library.
  - **`number-table`, `examples/number-table/`** (_`D318`_): its `README.md` documents the adapter (its code shown as text, as `README.md` does). First showcase, linked and shared with `README.md`: `planets.json`, planets' distances as a formatted table. Then inline `json` blocks: with each option, and with a non-numeric cell (a warning); an invalid one is shown as text only, as it would fail `check`.

- _`D321`_ (`live`; changes _`D318`_, _`D320`_; the deviations reported at the checkpoint, option chosen: "Approve and commit"): **Implemented with four deviations**: the `html` example's linked page is `examples/html/clock.html`, a 7-segment clock (HH:MM:SS), rather than an odometer, fitting the time theme; `number-table`'s warning (a non-numeric cell) is shown as text, not live, as this repository's check must pass without issues (`src/cli/check/index.integration.test.ts`); `number-table.js` imports Node's built-ins (`node:fs/promises`, `node:path`) to read a linked file, still with no dependencies; and `README.md`'s `html` showcase adapter part has a heading of its own, `### html showcases`, with the paragraph on planned showcase adapters and broken showcases moved above it.
- _`D322`_ (`live`; changes _`D319`_; fast path, options chosen: "Fast path (Rec.)", "As drafted (Rec.)", "Retheme it too (Rec.)"; the user: "those buttongs don't fit"): **`README.md`'s own minimal demonstrations show formatted numbers** instead of buttons and `rebeccapurple` text: monospace digits in one colour, `.` and `,` highlighted, decimals in another colour. The inline showcase (still the first, `README.showcase-1.html`) styles them with a `<style>` block; the resource is the same styles as `figures.css`; the linked page, `examples/button.html` renamed to `examples/figures.html`, splits one number in `en-US`, `de-DE` and `fr-FR` with `Intl.NumberFormat`'s `formatToParts()`; the themed fragment is a number coloured with `light-dark()`. _`D319`_'s `ts` part stands.
