# _`P15.3`_ The console out of the showcase frame

approved 2026-11-15 (option chosen: "Approve and commit (Rec.)"), without a zero-context review

## Goals

_`S12`_'s console out of the showcase frame (SPEC-S12-showcase-views.md): _`D503`_ (moved here by _`D545`_ (PLAN-P15-showcase-views.md)), _`D504`_, _`D505`_, _`D523`_'s 128 lines, _`D530`_'s clearing of the overlay, and _`D531`_ on the showcase frame's box. A child of _`P15`_ (PLAN-P15-showcase-views.md), the third of six (_`D541`_). Takes _`O82`_, _`O88`_ (SPEC-S12-showcase-views.md) and _`K22`_ (SPEC-pitfalls.md) (_`D543`_), and _`O84`_ for the plan decisions it changes.

Not in _`P15.3`_: the `console` view, its 8 lines and its "no output" placeholder (_`D499`_, _`P15.4`_'s); the `runtime` mark and its pending state (_`D507`_, _`D530`_, _`P15.5`_'s). Until _`P15.4`_, every showcase frame has the console panel over it, as today's hidden console panel; a showcase that only logs shows an empty showcase frame under it (_`D545`_).

Facts found while planning (2026-11-15):

- The console script (`consoleScript()`, `src/adapters/showcase/ts/console/`, 589 lines, tests 779) is inlined into every `ts`, `react` and `angular` page after `<div id="root">` and `<div id="showroom-console" hidden>`; it formats values (`describe()`, `format()`), keeps the newest 128 lines, picks its mode (alone or hidden) from what rendered, and grows `<body>`'s `min-height` while open, announced with `CONSOLE_GROWTH_EVENT`, which the frame script's growth guard exempts (_`D431`_ (PLAN-P10.5-console.md)).
- The frame script (`src/frame/`) is inserted first in every page, complete pages included, by `insertFrameScript()` (`src/showcases/`), so it runs before the page's own scripts (_`K22`_'s first half); outside the showroom (no parent window) it only applies the theme. Its messages are `ready` and `resize`; the showroom's `ShowcaseFrame` (`src/app/showcases/`) accepts only those whose `event.source` is its own iframe's window.
- `serve`'s error frame (_`D186`_ (PLAN-P4.3-serve.md)) gets the frame script too.
- `SHOWCASE_FRAME_ROOT_ID` is imported from `ts/console/` by the `react` and `angular` showcase adapters; `CONSOLE_PANEL_ID` and `getConsoleScript()` by the `ts`, `react` and `angular` integration tests and `src/adapters/showcase/ts/index.test.ts`.
- `ShowcaseFrame` is the bare iframe, used by blocks (with `minHeight` 64, _`D437`_ (PLAN-P10.5-console.md)) and by showcase frames shown inline (with no minimum).

## Decisions

The draft's choices 1–10 (`./.workflow/.temp/questions-p15.3/QUESTIONS.md`), option chosen: "Accept all (Rec.)".

- _`D559`_ (`live`; resolves _`O82`_'s messages (SPEC-S12-showcase-views.md); choice 1): **The frame contract's new messages**: `start`, posted by the frame script synchronously, first thing, before any of the page's own scripts run; and `console`, a batch of lines (`{ level, text, uncaught? }[]`) with `dropped`, the number of lines left out before them (_`D560`_). The showroom clears its console panel on `start`, so every load starts it afresh (_`D530`_): `serve`'s rebuild (a new URL), and the page reloading or navigating itself. `ready` and `resize` are unchanged. Rejected: clearing when the iframe's `src` changes (misses a page reloading itself; lines logged before `onLoad` would be cleared with the old ones).
- _`D560`_ (`live`; resolves _`O88`_'s volume (SPEC-S12-showcase-views.md); choice 2): **Lines are posted in batches**: the frame script queues each formatted line, and posts the queue at most every 50 ms (`CONSOLE_FLUSH_MS`, a timer started by the first queued line), each post holding the newest `CONSOLE_MAX_LINES` (128) lines and the number dropped before them; the queue is posted at once on `pagehide`. The showroom adds a batch in one state update. Rejected: a post per microtask (a `setInterval` logger still posts hundreds of messages a second, each a re-render); a post per line.
- _`D561`_ (`live`; choice 3): **A line is cut at 10 000 characters** (`CONSOLE_MAX_LINE_LENGTH`), ending in `… (<n> more characters)`, as a large value formatted as indented JSON can be megabytes, cloned through `postMessage` and kept in the showroom. Rejected: no limit, as today.
- _`D562`_ (`live`; resolves _`O88`_'s identity (SPEC-S12-showcase-views.md); choice 4): **Only the showcase frame's own window posts into its console panel**: the showroom keeps accepting only messages whose `event.source` is its iframe's window, as for `resize`, so a nested iframe or a `window.open` window can't; the frame script captures only its own window's console (a nested frame's own console isn't captured). Rejected: a per-load token in every message (guards nothing more: the page's own scripts could read it).
- _`D563`_ (`live`; changes _`D432`_ (PLAN-P10.5-console.md); choice 5): **The first uncaught error or rejected promise of each load opens the console panel by itself**, over the showcase, never taking focus; later ones only turn the counter red, until the next load. _`D432`_'s "after the showcase rendered" goes with detecting it (_`D503`_). Rejected: never opening by itself (a crash that empties the page leaves only a red counter, changing _`D377`_ (SPEC-S10-presentation.md)).
- _`D564`_ (`live`; changes _`D436`_ (PLAN-P10.5-console.md); choice 6): **The open console panel leaves its 32 px room at the top only in a block** (a `ShowcaseFrame` property), where the code pane's cycling button floats over the showcase frame; a showcase frame shown inline uses its whole height. _`P15.4`_ moves the button into the header bar (_`D546`_ (PLAN-P15-showcase-views.md)), and drops the room. Rejected: every showcase frame, as today.
- _`D565`_ (`live`; refines _`D531`_ (SPEC-S12-showcase-views.md); choice 7): **Once anything is logged, a showcase frame's box is at least the counter's row high** (32 px), so a short showcase frame shown inline (a page that only logs is about 16 px) holds the counter and the fading lines; opening the console panel grows the box to fit it (_`D531`_), the showcase frame keeping its own height inside. A block's showcase frame keeps its 64 px minimum (_`D437`_ (PLAN-P10.5-console.md)). Rejected: no minimum, the counter overflowing the text above it.
- _`D566`_ (`live`; choice 8): **The console panel lives in `src/app/console/`**: the console's state as a pure function of the showcase frame's messages and the user's actions (the lines kept, the dropped count, the count, the unseen errors, open or not, opened by itself once per load), unit-tested; `ConsolePanel`, the overlay, rendered by `ShowcaseFrame` inside a positioned box around its iframe (inline showcases and blocks alike, _`D526`_ (SPEC-S12-showcase-views.md)); the fading lines' timers in an effect, the lines to show computed from their times by a pure function; Escape closes it while focus is in the panel (a key pressed inside the showcase frame never reaches the showroom). The panel's constants move with it (8 lines, 3 fading lines, 3 s and a 1 s fade, the 32 px room). Rejected: inside `src/app/showcases/`.
- _`D567`_ (`live`; refines _`D434`_ (PLAN-P10.5-console.md); choice 9): **In a showcase frame taller than the screen, the console's parts stay at the bottom of the showcase frame's box**, possibly out of view, as today; sticking to the viewport's bottom is an idea for later (SPEC-S12-showcase-views.md › Ideas and later). Rejected: sticky now (more layout work).
- _`D568`_ (`live`; supersedes _`D431`_ (PLAN-P10.5-console.md); choice 10): **What goes**: the `ts` showcase adapter's `console/` folder (the console script and its tests); `SHOWCASE_FRAME_ROOT_ID` moves to `src/adapters/showcase/ts/`, imported from there by the `react` and `angular` showcase adapters; the page holds `<div id="root"></div>` and the module alone. The formatter (`describe()`, `format()`) moves into the frame script, with `CONSOLE_LEVELS` and `CONSOLE_MAX_LINES` into `src/frame/`. `CONSOLE_GROWTH_EVENT` and the frame script's exemption for it go, as the panel no longer grows the page; `MAX_REPEATED_GROWTHS` stays as it is. Rejected: keeping `console/` for the ids alone.

## Steps

1. **The frame script** (`src/frame/`): the console captured at its start (every `console.log`, `info`, `warn`, `error` and `debug` call, still reaching the browser's console; uncaught errors and rejected promises), formatted inside the showcase frame with the formatter moved from the console script (_`D504`_, _`K22`_), posted as the new messages; `isFrameMessage()` and the message types; `CONSOLE_GROWTH_EVENT` and its exemption removed. Tests: `src/frame/index.test.ts` on its stubbed `window` (the formatting tests moved from the console script's; capture before `DOMContentLoaded`; the messages, their order and batching with fake timers; the caps; `pagehide`; uncaught errors and rejections; no capture of posting outside the showroom).
2. **The `ts` showcase adapter**: the console script and its tests deleted, the page holding the showcase frame root and the module alone (_`D505`_), `SHOWCASE_FRAME_ROOT_ID` moved; `react` and `angular` imports. Tests: the page's assertions in `src/adapters/showcase/ts/index.test.ts`, the `ts`, `react` and `angular` integration tests, `build()`'s `e2e` and the `serve` tier.
3. **The showroom's console panel** (`src/app/console/`, `src/app/showcases/`): the console's state and its updates; `ConsolePanel` over `ShowcaseFrame`'s iframe, in the showroom's theme (FluentUI tokens): the fading lines, the counter (red with the unseen errors), the open panel with its header bar and close button, Escape, opened by itself once per load, cleared on every load (_`D505`_, _`D530`_), the box growing to fit it open (_`D531`_). Tests: the state's updates (every message, the 128 lines and the dropped line, clearing, counting, opening once), the fading lines' selection by time, and `ShowcaseFrame` and `ShowcaseBlock` rendered on the server with given console state (the counter's text and label, the open panel, nothing while nothing is logged).
4. **Documentation**: `README.md` (`ts` showcases: the page, the console panel now in the showroom for every showcase adapter, `html` included; `react`, `angular` and the code pane's paragraphs where they name it), the `ts`, `react` and `angular` examples' wording; `AGENTS.md` (Layout: `console/` gone, `src/app/console/` added; the console script's and the growth guard's gotchas; Testing); `CONTRIBUTE.md` (the architecture; the Glossary's **Console panel**, **Frame script** and **Showcase frame root**, as _`D524`_ words them, the `console` view left for _`P15.4`_); the plan decisions this changes marked (_`O84`_): _`D249`_ (PLAN-P7.1-ts.md), _`D424`_–_`D438`_ (PLAN-P10.5-console.md), _`D437`_'s reason.
5. **Green**: `npm run ci`; the dogfood `serve` started, and a scratch host in `./.workflow/.temp/p15.3-check/` (a copy, never a fixture) with `html`, `ts`, `react` and `angular` showcases that log, log before the page's scripts (an `html` page's `<head>` script), throw, reject, log in a loop, log huge values, and reload themselves, inline and in blocks, for the user's check in a browser, in both themes.
