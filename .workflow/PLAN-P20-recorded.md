# _`P20`_ Recorded showcases and the `cs` showcase adapter

approved 2026-11-17, for its split and _`P20.1`_ (option chosen: "Approve and commit (Rec.)"), after its zero-context review

_`S15`_ (SPEC-S15-recorded-showcases.md) and _`S16`_ (SPEC-S16-csharp.md): showcases built and run on the machine running `showroom`, in a host copy, their console output and exit code recorded and shown in the showroom; and the built-in `cs` showcase adapter, the first to record, building C# file-based apps with the host's .NET SDK. Its choices were settled planning it on 2026-11-17 (`./.workflow/.temp/questions-p20/QUESTIONS.md`) as _`D768`_–_`D781`_, and its zero-context review of 2026-11-17 (consistency and security; `./.workflow/.temp/review-p20/REVIEW.md`) as _`D782`_–_`D790`_, revising _`S15`_ (_`R57`_).

Found in the code while planning: `buildShowcases()` (`src/showcases/`) builds showcases one after another, never at once; `serve`'s host watcher is told that something changed (`notify()`), not what; Vite's watcher never sees `node_modules/` or `.git/`; a code block showcase's virtual file is `<stem>.showcase-<n>.<ext>`, or its `file=` name when named; `PLANNED_SHOWCASE_ADAPTER_NAMES` (`src/adapters/showcase/registry/`) is empty; `showroom` starts no process yet.

#### Steps

1. **The interface** (`src/adapters/showcase/`, _`D768`_): `ShowcaseAdapter.recorded` (_`D769`_) and `hostCopy` (_`D774`_); `ShowcaseBuildRequest`'s `project`, `stack` and `hostCopy` (`{ root, run() }`, present when the showcase adapter declares `hostCopy`); `check?()`'s `project` and `stack`; `ShowcaseBuildResult.recording` (`ShowcaseRecording`: its lines in the frame script's format and limits, the dropped counts, `exitCode`, `timedOut`); new exported types `ShowcaseRecording`, `ShowcaseHostCopy`, `ShowcaseRun` (what `run()` resolves to: the recording, and the raw capped output for a build's diagnostics).
2. **Running processes** (new internal `src/processes/`): resolving a command from the `PATH` (_`D771`_); spawning it under the limits (_`D772`_, _`D773`_, _`D777`_): the cleaned environment, the closed input, the time limit, the group kill, the streaming output cap; standard output as `log`, standard error as `error` lines (_`D706`_); the host copy's path made root-relative (_`D779`_).
3. **The host copy** (new internal `src/host-copy/`): made in the command's temporary folder (_`D776`_), from the union of the declared copies (_`D774`_), with symbolic links kept and those leading outside the root left out (_`D735`_), copy-on-write where available (_`D687`_); virtual files written at their paths, never through a link; synced each run (_`D775`_); removed at the command's end and on `SIGINT` and `SIGTERM`.

#### Glossary wording (_`D711`_, _`D736`_ (SPEC-S15-recorded-showcases.md)), proposed

- **Recorded showcase** (new): A showcase that its showcase adapter builds and runs on the machine running `showroom`, recording its console output and exit code, which the showroom shows in place of a showcase frame's console.
- **Host copy** (new): `showroom`'s copy of the host repository, in a folder of the user's cache, with virtual files written where they belong, in which the showcase adapters that ask for it build (and record) showcases, so that the host repository itself is never written to by `showroom`.
- **Showcase adapter** (changed): An implementation of the common interface for building showcases of one kind of code (HTML, TypeScript, React, Angular, or the host repository's own; C# with _`P20.2`_) into a showcase frame or a recording, chosen per showcase by its marker.
- **Custom showcase adapter** (changed): … ("bring your own build"), which may record (_`D719`_); experimental until its interface is declared stable.
- **Host check** (changed): A showcase adapter's check of the host repository's host requirements (`check?()`), run once per run with the showcases using it, only with trust.
- **Console panel** (changed): The showroom's list of what a showcase frame's page writes to the browser's console, its uncaught errors and its rejected promises, as the frame script reports them, shown as the `console` view, or over the `demo` view behind fading lines and a counter that opens it; or of a recorded showcase's recording, shown as the `console` view only.
- **Status mark** (changed): … and `runtime` while its page runs, or from its recording; ✓, ⚠ or ✗.
- **Shown host information** (changed): … and, where it builds and a view loads it, its showcase frame's URL, or its recording.
