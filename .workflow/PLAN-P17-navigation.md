## Decisions

- _`D641`_ (`live`; option chosen: "Add github-slugger (Rec.)"; rejected: reimplementing GitHub's slugs, skipping anchor warnings): **`github-slugger` (`^2.0.0`) becomes a dependency**, the version `rehype-slug` already installs, so `check`'s heading ids are the showroom's by construction (_`D637`_).
- _`D642`_ (`live`; Q1, option chosen: "(a) In Node, by check()"; rejected: resolving it in the showroom too): **`check()` resolves the navigation**: globs expanded, labels from first headings, paths matched, anchors split off; the resolved tree is `HostInformation.navigation`, carried to the showroom in the shown host information (a change to it reloads `serve`'s page, as `getShownChange()` compares everything it doesn't exempt).
- _`D643`_ (`live`; resolves _`O90`_; Q2, option chosen: "(a) \"/\", first heading or name"; rejected: the root `README`'s path only, the label `README`): **The path `/` always names the home page**, and so does the root `README`'s path; with no `title`, it is labelled by the root `README`'s first heading, else the project's name.
- _`D644`_ (`live`; resolves _`O91`_; Q3, option chosen: "(a) .gitignore-style"; rejected: plain globs with `picomatch`): **A glob is a `.gitignore`-style pattern**, matched with `ignore` against the documentation files' paths, as the `documentation` patterns are; a `path` is a glob when it holds `*`, `?` or `[`; a leading `!` is invalid (`validateConfiguration()`). As in `.gitignore`, a pattern without a slash (other than a trailing one) matches at any depth.
- _`D645`_ (`live`; resolves _`O92`_; Q4, option chosen: "(a) First of any level"; rejected: the first level-1 heading only): **A file's first heading is its first heading of any level**, in document order (ATX or setext), as plain text: the text of its text nodes, code spans, links and emphasis, without images and HTML, trimmed; an empty one counts as none.
- _`D646`_ (`live`; Q5, option chosen: "(a) As a route"; rejected: exact paths): **A page's `path` is matched as a route is**: case-insensitively (the showroom's documentation file lookup), with a leading `./` dropped.
- _`D647`_ (`live`; Q6, option chosen: "(a) As listed"; rejected: exporting only the configuration's type): **Exports**: `NavigationEntry` (the configuration's item: `{ title?, path }` or `{ title, items }`) and `Configuration.navigation?`; `NavigationItem` (a resolved item: a page `{ kind: 'page', label, path, anchor? }`, the home page's `path` empty; a URL `{ kind: 'url', label, url }`; a group `{ kind: 'group', label, items }`) and `HostInformation.navigation?`; `DocumentationFile.heading?`, its first heading (_`D645`_). The showroom's own internal `NavigationItem` (`src/app/navigation/`) is renamed `ShownNavigationItem`.
- _`D648`_ (`live`; Q7, option chosen: "(a) At the file"; rejected: at `showroom.json`): **A documentation file the navigation doesn't list is warned about at the file itself** ("not in the navigation"); the navigation's other issues (_`D637`_) point at `showroom.json`.
- _`D649`_ (`live`; Q8, option chosen: "(b) Own navigation"; rejected: keeping the default navigation, the agent's recommendation): **This repository's `showroom.json` gets a `navigation` of its own**, listing every documentation file (its check must pass without issues), proposed as:
  - `/` (labelled by `README.md`'s first heading, `showroom`);
  - a group `Examples`: `html`, `ts`, `react`, `angular`, `number-table`, each titled by its showcase adapter's name (their first headings are their mock projects' names);
  - a group `Contributing`: `CONTRIBUTE.md` ("Contributing"), `PUBLISH.md` ("Publishing"), `AGENTS.md` ("Agents"), `CLAUDE.md` ("Claude"), `WORKFLOW.md` ("Workflow"), `WORKFLOW.custom.md` ("Workflow customizations");
  - `LICENSE.md` ("License").

  The default navigation stays covered by the unit tests and by the fixtures `check()` and `build()` run on.

## Steps

1. **Configuration** (`src/configuration/`): `Configuration.navigation` and `NavigationEntry`; `validateConfiguration()` checks it recursively, with messages naming the item's position (e.g. `"navigation" item 2.1`): a list; each item an object with only `title`, `path` and `items`; a page or a group (_`D631`_); a non-empty string `title` where given, required on a group and a URL (_`D633`_), refused on a glob; a non-empty `path`; a non-empty `items`; no leading `!` (_`D644`_). Tests: every valid shape, each invalid one.
2. **Headings** (`src/markdown/`): `scanMarkdown()` also returns the headings (`{ text, id, line }`, ids from `github-slugger`, one slugger per file, as `rehype-slug` gives them); `DocumentationFile.heading` set by `check()` (_`D645`_). Tests: levels, setext, code spans, links, emphasis, images, HTML, duplicates (`-1` ids), empty headings, and the ids against `rehype-slug`'s own on the same Markdown (rendered in `src/app/markdown/`'s tests).
3. **Resolution** (new `src/navigation/`, Node-free, never re-exported; `HostInformation.navigation` and `NavigationItem` in `src/host/`): `resolveNavigation(entries, documentation, project)` returns the resolved items and the issues: URLs (a scheme, `^[a-z][a-z0-9+.-]*:`), `/` and the root `README`'s path as the home page (_`D643`_), paths matched as routes (_`D646`_), anchors split off and checked against the headings' ids, globs expanded in path order skipping files listed explicitly and ones an earlier glob took (_`D634`_), labels (_`D633`_), duplicates and unlisted files (_`D636`_, _`D637`_, _`D648`_). `check()` calls it when the configuration has `navigation`. A new fixture `navigation` (pages, anchors, a URL, nested groups, globs with overlaps, `/`, a hidden file) and `navigation-errors` (every error and warning). Tests: `src/navigation/` on hand-written values; `check()` on both fixtures; `index.test.ts`'s export list.
4. **Shown host information** (`src/vite/`, `src/app/host/`): `ShownHostInformation.navigation`, passed through; `getShownChange()` reloads on a change (a test).
5. **The showroom** (`src/app/navigation/`, `src/app/layout/`): `getNavigationItems()` builds `ShownNavigationItem`s, a tree: the configured navigation, or the default one (_`D639`_: fixed `README`, `CONTRIBUTING`, `LICENSE`; every other file by its first heading, by its path where another item has the same label; every documentation file's item with its path as its tooltip, `title`). The layout renders groups as collapsible sections (a button with `aria-expanded`, expanded at first, each level indented), keeps the group holding the current item expanded, marks the current item (a page's anchor ignored for that), and opens URL items in a new tab (`target="_blank"`, `rel="noopener noreferrer"`) (_`D638`_). Tests: the items (default and configured, clashes, tooltips, the home page), and the layout rendered on the server (groups, nesting, `aria-expanded`, the current item, a URL's attributes). The user checks it in a browser (collapsing, the narrow layout's overlay drawer).
6. **Dogfooding** (_`D649`_): this repository's `showroom.json` gets its `navigation`; `npm run ci` (`ci:showroom`) passes without issues.
7. **Documentation**: `README.md` (`# Usage` › Configuration: `navigation`, with an example in a code block; Documentation files: the default navigation's labels; `showroom check`'s new errors and warnings; `# API`: the new types and fields, `tsc`-checked), `CONTRIBUTE.md` (the Glossary term "Navigation", accepted with _`S13`_; the project structure: `src/navigation/`), `AGENTS.md` (Layout, Testing, Exports; `github-slugger` as a dependency).

Each step runs the affected unit tests; the checkpoint runs `npm run ci`, and starts the dogfooding `showroom serve` for the user's browser check.
