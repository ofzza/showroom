A built-in showcase adapter showing a JSON Schema's definitions, and how they reference one another, as a diagram drawn with Mermaid. From the discussion of 2026-11-17 (the user: "JSON schema, displaying a JSON schema represented data models and their interconnectedness as a mermaid graph type presentation"; then "I am most interested to building the JSON schema adapter [...] I would start with JSON schema one"). The search for an existing library of 2026-11-17 found none mapping a JSON Schema to a diagram of its models; Mermaid draws, and `../tsschema` reads. Its choices were settled as _`D806`_–_`D819`_.

## Decisions

- _`D803`_ (`live`, refined by _`D806`_–_`D808`_, _`D810`_, _`D811`_, _`D816`_, _`D818`_, _`D827`_; the user's words, quoted above): **A built-in JSON Schema showcase adapter** shows one JSON Schema as a diagram: each definition a node, each reference from one definition to another an edge, drawn with Mermaid in the showcase frame. It is the first built-in showcase adapter whose showcase frame is derived from its entry point's content, rather than built from the host's files (`html` copies files, and runs nothing either).
- _`D804`_ (`live`, refined by _`D805`_, _`D806`_, _`D809`_, changed by _`D817`_, _`D821`_, _`D822`_; the user: "Mostly because all the effort going into `tsschema` is a double win from my perspective, I would then want to go with `tsschema`."): **The JSON Schema showcase adapter reads a schema with `@ofzza/tsschema`'s runtime reflection** (`reflect()`, its definitions, and their type descriptors), never by walking JSON Schema keywords itself, so what `tsschema` learns to read reaches the diagram without changing the adapter (except for a new kind of type descriptor). Rejected: `@apidevtools/json-schema-ref-parser` with a walk of our own; `schyma`, `studio-json-schema` and `@stoplight/json-schema-viewer` (see the evidence below).
- _`D805`_ (`live`, refined by _`D817`_, _`D819`_; refines _`D804`_; the user: "For now, let's use it as it is and accept all of its limitations [...] Once `tsschema` has been upgraded we will follow along."): **`tsschema` is used as it is, with its limitations**: definitions are only found in `$defs` (a draft-04/07 schema's `definitions` show none, _`L16`_), and only in the one file the showcase names (a `$ref` into another file resolves to nothing, _`L17`_); `additionalProperties` and tuples are described as `unknown` (_`L18`_). `showroom` follows `tsschema`'s releases: changes only ever flow from `tsschema` to `showroom`, and `tsschema` is never changed for `showroom`'s sake as part of `showroom`'s work.

Evidence (the search of 2026-11-17): `json-schema-to-diagram` asks an OpenAI model for the diagram (abandoned since 2024); `schyma` (a React Flow graph) is little used, on `reactflow` 11, and fetches remote `$ref`s; `studio-json-schema` is an application, draft 2020-12 only; `@stoplight/json-schema-viewer` is maintained, but a tree of one schema rather than a graph of models; Mermaid (MIT, 12.3) is mature, and GitHub renders its source in Markdown.

### The draft's choices

- _`D806`_ (`live`, refined by _`D819`_, changed by _`D845`_ (PLAN-P21-jsonschema.md); refines _`D803`_, _`D804`_; Q3, option chosen: "Both showroom's own (Rec.)"; a new dependency, asked on its own): **Mermaid and `@ofzza/tsschema` are `showroom`'s own `dependencies`**, so a JSON Schema showcase needs nothing of the host, in any host repository (.NET ones included), and `showroom` controls both versions. Every install of `showroom` grows by Mermaid (about 150 MB unpacked with its dependencies, against FluentUI's 378 MB installed); a showcase frame should load only what the class diagram needs, settled by _`O130`_'s spike (_`K29`_ (SPEC-pitfalls.md)). Rejected: Mermaid from the host, verified by the host check (a host without a `package.json` couldn't use it); both from the host (the host's `tsschema` would have to match what `showroom` supports, a two-repository sync again).
- _`D807`_ (`live`; refines _`D803`_; Q1, the user: "I prefer `jsonschema` - none of the adapters so far use `-` and I prefer to keep it that way"): **The JSON Schema showcase adapter is named `jsonschema`** (`showcase=jsonschema`): no built-in showcase adapter's name has a hyphen. Rejected: `json-schema`; `schema` (ambiguous).
- _`D808`_ (`live`, refined by _`D826`_, _`D829`_; refines _`D803`_; Q2, the user: "Agreed with recomendation on rest"): **A `jsonschema` showcase is JSON**: a linked `.json` file (e.g. `person.schema.json`), or a `json` code block; a named showcase gets `.json`. Rejected for now: YAML (another dependency, a parser).
- _`D809`_ (`live`, refined by _`D830`_; refines _`D804`_; Q4, the user: "Agreed with recomendation on rest"): **The diagram's Mermaid source is written in Node, at build time**: `tsschema` reads the schema, the adapter writes the Mermaid source, and the showcase frame's page only draws it with Mermaid, so the mapping is unit-tested without a browser, and its issues reach `check --showcases` and `build`. Rejected: everything in the showcase frame (issues seen only in a browser); an SVG drawn at build time (Mermaid needs a real browser to lay out).
- _`D810`_ (`live`, changed by _`D831`_; refines _`D803`_; Q5, the user: "Agreed with recomendation on rest"): **The diagram follows the showroom's theme**: drawn with Mermaid's `default` or `dark` theme from the frame script's theme, and redrawn when it changes. Rejected: always light.
- _`D811`_ (`live`, refined by _`D812`_, _`D813`_, _`D830`_; refines _`D803`_; Q6, the user: "Agreed with recomendation on rest"): **The diagram is a Mermaid `classDiagram`**: properties with their types in each node, enums as `<<enumeration>>`, inheritance and associations as different arrows, associations with labels and multiplicities. Rejected: `erDiagram` (no enums or inheritance), `flowchart` (boxes and arrows only).
- _`D812`_ (`live`, refined by _`D814`_, _`D823`_; refines _`D811`_; Q7, the user: "Agreed with recomendation on rest"): **Every definition is a node**: a model with its properties (name, and type as text, e.g. `string`, `Address`, `Item[]`, optional ones marked), an enum with its values (`<<enumeration>>`), and any other definition (e.g. an alias of a formatted string, or a union) with a stereotype naming its kind. Rejected: models and enums only.
- _`D813`_ (`live`, refined by _`D823`_, changed by _`D831`_; refines _`D811`_; Q8, the user: "Agreed with recomendation on rest"): **References are labelled associations, and `allOf` is inheritance**: a property referencing a definition (directly, through an array, or as a member of an `anyOf`/`oneOf`, nullable or not) gives an association labelled with the property's name and multiplicity (`1`, `0..1`, `*`); a definition whose `allOf` holds a reference inherits from it; a definition that is an `anyOf`/`oneOf` of references links to each member. Rejected: one plain edge per pair of definitions.
- _`D814`_ (`live`, changed by _`D822`_, _`D824`_; refines _`D812`_; Q9, the user: "Only make root a node if it is a model. If it only contains definitions, there is no need for it to be in the grapph"): **The schema's root is a node only when it is a model** (it has `properties`), named by its `title`, or else by its file's name; a root holding only `$defs` is not in the diagram. Rejected: only `$defs` definitions as nodes.
- _`D815`_ (`live`, refined by _`D829`_; refines _`D501`_ (SPEC-S12-showcase-views.md); Q10, the user: "Agreed with recomendation on rest"): **The `jsonschema` showcase adapter's default views are `demo`**, the diagram, as `html`'s, `react`'s and `angular`'s; `view=demo,source` adds the schema below it. Rejected: `source,demo`.
- _`D816`_ (`live`, changed by _`D820`_, _`D825`_, refined by _`D826`_, _`D828`_; refines _`D803`_; Q11, the user: "Agreed with recomendation on rest"): **A `jsonschema` showcase has a `schema` check**: the file is valid JSON (an error at its line otherwise), holds an object, and `tsschema` reads it; its status marks are `schema` and `runtime` (Mermaid's drawing errors reach the console panel). Rejected: no check of its own.
- _`D817`_ (`live`, changed by _`D821`_; refines _`D805`_, changes _`D804`_; Q12, the user: "Agreed with recomendation on rest"): **`tsschema`'s limitations are warned of, and references into other files are drawn**: a warning when a schema has `definitions` and no `$defs` (not read yet, _`L16`_ (SPEC.md)), when the diagram would be empty, and one per showcase listing its `$ref`s into other files (_`L17`_ (SPEC.md)), each drawn as a dashed node marked "outside this file", its edge kept. Spotting them reads the `definitions` and `$ref` keywords directly, the one exception to _`D804`_, until `tsschema` reports them itself. Rejected: warnings only; nothing.
- _`D818`_ (`live`; refines _`D803`_, _`D747`_ (PLAN-P19-trust.md); Q13, the user: "Agreed with recomendation on rest"): **A `jsonschema` showcase is built only with trust**, as every showcase is (_`D740`_ (SPEC-S14-trust.md)), although nothing of the host runs to build it: this decides the case _`D747`_ (PLAN-P19-trust.md) foresaw (a showcase adapter that runs nothing), with no exemption. Rejected: built without trust (a first exception to the rule).
- _`D819`_ (`live`; refines _`D805`_, _`D806`_; Q14, the user: "Agreed with recomendation on rest"): **`@ofzza/tsschema` is pinned exactly** (an alpha: the release current when it is added, no range), and bumped as a change of its own; a test asserting one of its limitations says so in a comment naming its _`L…`_ tag (SPEC.md), so the bump that lifts it shows what to update. Rejected: a `^` range.

### The zero-context review of 2026-11-17

Rejected: `schema` in place of `build` (changes _`D507`_, _`D523`_).
- _`D821`_ (`live`, refined by _`D859`_ (PLAN-P21-jsonschema.md); changes _`D817`_, _`D804`_; review 2026-11-17 R2 (C6, F6, F7)): **References `tsschema` can't resolve are warned of, not drawn**: `tsschema` describes them as `unknown`, without their `$ref`, so one warning per showcase lists every `$ref` that isn't a `#/$defs/<name>` of the schema's own `$defs`, grouped by reason (into another file, _`L17`_ (SPEC.md); in the same file but not read yet, e.g. `#/definitions/X`, `#/$defs/Missing`, `#`, a pointer into a definition, an escaped name, `$id` or `$anchor`), found by a scan of the raw JSON's `$ref` keywords. No "outside this file" nodes until `tsschema` reports unresolved references itself. Rejected: dashed nodes where a property's own fragment holds the `$ref` (a second walk in step with `tsschema`); _`D817`_'s full walk.
- _`D822`_ (`live`, refined by _`D847`_ (PLAN-P21-jsonschema.md); changes _`D814`_, _`D804`_; review 2026-11-17 R3 (F4)): **A model is what `tsschema` describes as one**: `type: "object"` with `properties` (_`D814`_'s "it has `properties`" read so); `properties` without `type: "object"` (common in `allOf` members) describe as `unknown` (_`L19`_ (SPEC.md)), and are warned of, a definition or the root at a time, by reading the raw JSON's `properties` and `type`. Rejected: the known open issue alone.
- _`D823`_ (`live`, changed by _`D831`_; refines _`D812`_, _`D813`_; review 2026-11-17 R4 (F5, F12, F13, C11)): **The mapping's details**: a definition described as an `allOf` (implicit or explicit, flattened) is one class merging its model members' properties, each reference member an inheritance edge, any other member named by stereotype; a definition that is an `anyOf`/`oneOf` of references links to each member with a dependency arrow (`..>`) labelled `anyOf` or `oneOf`; an alias (`A: { $ref: B }`) is an `<<alias>>` node with a `..>` edge to its target; multiplicities are `1` (required, not nullable), `0..1` (optional or nullable, a `oneOf` with a `null` member included) and `*` (an array; `1..*` with `minItems` of 1 or more; a nested array is `*`, its type text e.g. `Item[][]`); an inline object's type text is `object`, an inline enum's its values; no anonymous nodes. Rejected: leaving them to planning.
- _`D824`_ (`live`, refined by _`D860`_ (PLAN-P21-jsonschema.md); changes _`D814`_; review 2026-11-17 R5 (C7, F14)): **The root's node is named by its `title`, else by the showcase's name if it has one, else `root`**; a root that is only a `$ref` beside its `$defs` marks the referenced definition `<<root>>`. Clashing names are harmless, as nodes have generated ids (_`D830`_). Rejected: the file's name (a code block's is a virtual file's, `README.showcase-N.json`).
- _`D825`_ (`live`; changes _`D816`_; review 2026-11-17 R6 (C-Q2, F10)): **A schema that isn't an object is an error, except a boolean schema** (`true`, `false`), which gets the warning that nothing shows; `reflect()` never throws, so "`tsschema` reads it" is no condition of its own. Rejected: an error for a boolean schema too.
- _`D826`_ (`live`, changed by _`D857`_ (PLAN-P21-jsonschema.md); refines _`D808`_, _`D816`_; review 2026-11-17 R7 (C15, F10)): **A `jsonschema` showcase is strict JSON**: a byte order mark is accepted, comments are an error; a syntax error is placed at its line from the parse position, and is reported by the showcase adapter's validation (plain parsing, before trust is decided, as the built-in showcase adapters' validation is, _`D740`_ (SPEC-S14-trust.md)). Rejected: JSON with comments (through `json5`).
- _`D827`_ (`live`; refines _`D803`_; review 2026-11-17 R8 (C5)): **The Glossary's "Showcase adapter" names a JSON Schema among what a showcase adapter builds**; "model" and "definition" are JSON Schema's own terms (a definition is an entry of `$defs`; a model, _`D822`_), not Glossary terms.
- _`D828`_ (`live`; refines _`D816`_; review 2026-11-17 X9 (C9)): **The showcase frame's page reports Mermaid's failures with `console.error`** (a rejected `render()`, rather than Mermaid's own error drawing), so the frame script captures them and `runtime` shows ✗.
- _`D829`_ (`live`; refines _`D808`_, _`D815`_; review 2026-11-17 X10 (C10, C-Q3)): **A `jsonschema` showcase's included files are tabs only**, never read for its `$ref`s (until _`L17`_ (SPEC.md)); a `$ref` to a virtual `.json` of the same documentation file is into another file; the `source` view highlights the schema as JSON.
- _`D830`_ (`live`, refined by _`D841`_, _`D854`_ (PLAN-P21-jsonschema.md); refines _`D809`_, _`D811`_; review 2026-11-17 X12 (F1, F2), for correctness): **The Mermaid source is data, and the schema's text only display text**: it ships with the showcase frame as data (a file of its own, or escaped JSON), never inline as markup; every node gets a generated id (ASCII letters and digits), the schema's names only ever its display text; one escaper writes all display text (line breaks to spaces, Mermaid's special characters encoded, a length cap); the adapter writes no `click`, `link`, `callback` or `%%{init}%%`, and `style` and `classDef` only from its own constants; a test feeds a schema of awkward names and texts (line breaks, `}`, quotes, leading `-` and `#`, `()`, `~T~`, `$$`, `</script>`) and asserts the source.
