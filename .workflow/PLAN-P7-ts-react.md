# _`P7`_ Showcases: the `ts` and `react` showcase adapters

implemented 2026-11-13 (both child segments implemented); approved 2026-11-13 (option chosen: "Approve and commit (Rec.)"); segmentation and _`D242`_–_`D245`_ decided 2026-11-12; edited 2026-11-12 after its zero-context review, before approval (_`D244`_ narrowed to bundling, with its pinned Vite settings; child segment summaries completed; open points _`O30`_–_`O43`_ added)

## Goals

The `ts` and `react` built-in showcase adapters (_`D97`_, SPEC-S6-showcases.md), in the order _`D100`_ and _`D229`_ (SPEC-S6-showcases.md) set: `ts` first (_`S6.7`_), then `react` on top of it (_`S6.3`_), working in `check --showcases`, `build` and `serve` (_`D82`_, _`D102`_, SPEC-S6-showcases.md). The `angular` showcase adapter (_`S6.4`_, _`K9`_ (SPEC-pitfalls.md)) is not part of _`P7`_.

## Child segments

Each is planned, approved, implemented and checkpointed on its own, in this order (_`D242`_):

- **_`P7.1`_ The `ts` showcase adapter** (implemented 2026-11-13; split into _`P7.1.1`_ building and _`P7.1.2`_ type checking by _`D246`_ (PLAN-P7.1-ts.md); [See The `ts` showcase adapter](./PLAN-P7.1-ts.md)): its `validate()` (options, `typeCheck` among them) and host requirements in `check`; the entry point and its virtual files as Vite modules, built with `showroom`'s own Vite (_`D235`_ (SPEC-S6-showcases.md), _`D244`_), in `check --showcases` and `build`, with the files each build reads (`reads`) for the host watcher; the console panel and the page container (_`D233`_ (SPEC-S6-showcases.md)); type checking with the host's TypeScript and nearest `tsconfig.json` (_`D234`_ (SPEC-S6-showcases.md)); build and type errors mapped to their lines, in code blocks or linked files (_`D102`_ (SPEC-S6-showcases.md)); what a showcase can import (_`D236`_ (SPEC-S6-showcases.md)); `serve` rebuilding on change (_`D243`_).
- **_`P7.2`_ The `react` showcase adapter** (implemented 2026-11-13; [See The `react` showcase adapter](./PLAN-P7.2-react.md)): built on _`P7.1`_; the mount module rendering the default export with `createRoot` (_`D230`_, _`D237`_ (SPEC-S6-showcases.md)), `tsx`/`jsx` entry points (_`D238`_), the default-export check (_`D239`_), no StrictMode (_`D240`_), the theme (_`D241`_, all SPEC-S6-showcases.md); type checking React showcases; React ≥ 18 as a host requirement (_`O29`_); a React 18 fixture with its own install (_`D245`_).

## Decisions

- _`D242`_ (`live`): **Two child segments: _`P7.1`_ `ts`, then _`P7.2`_ `react`**, each planned, approved, implemented and checkpointed on its own (option chosen: "P7.1 ts, P7.2 react (Rec.)"). Rejected: one segment for both (a larger change, fewer checkpoints); a third child for a Vite dev server in `serve` (see _`D243`_).
- _`D243`_ (`live`): **`serve` rebuilds `ts` and `react` showcases on change, as it does `html` ones**: each run of the host watcher builds them with Vite's `build` into memory, and the showroom reloads their showcase frames by _`P4.3`_'s events (option chosen: "Rebuild, as html (Rec.)"). A Vite dev server with hot updates for showcase frames is deferred (_`L11`_ (PLAN.md)); rebuilding only the showcases a change affects is _`O28`_ (PLAN-P4.3-serve.md), taken up in _`P7.1`_ by _`O34`_'s criterion. Rejected: a second Vite dev server in middleware mode now (works, see _`D244`_'s evidence, but more to build and test in `serve`); leaving it to _`P7.1`_.
- _`D244`_ (`live`; resolves _`K10`_ (SPEC-pitfalls.md) for bundling React, and _`K14`_ (SPEC-pitfalls.md) for bundling with Vite-based showcase adapters): **For bundling, framework code comes from the host by module resolution.** `showroom`'s own Vite compiles TypeScript and JSX (its built-in Oxc transform, automatic JSX runtime; no `@vitejs/plugin-react`); virtual files (_`D91`_ (SPEC-S6-showcases.md)), and the modules `showroom` generates for a showcase (e.g. `react`'s mount module), are Vite virtual modules with absolute paths in the documentation file's folder, so their relative and bare imports (`react`, `react-dom/client`, `react/jsx-runtime`) resolve from there up to the host repository's `node_modules`. Nothing else is loaded from the host for bundling; type checking loads the host's TypeScript (_`D234`_ (SPEC-S6-showcases.md)), which stays open (_`O30`_, _`O31`_). The build's Vite configuration is inline and pins what Vite would otherwise take from the host: `configFile: false`, `envDir: false`, `publicDir: false`, `cacheDir` in the build's scratch folder (_`D105`_ (PLAN-P4-showcases.md)), none of the showroom's own plugins, and never `getReactAliases()` (`src/vite/`), which would force `showroom`'s React into the showcase; PostCSS and tsconfig JSX settings are _`O32`_.
  - Evidence: Spike 2026-11-12 (option chosen: "Accept (Rec.)"): Vite 8.3.7 from this repository, fake hosts outside it on React 18.3.1 and 19.3.1. `build` (`write: false`, the mount module as the input): each bundle holds only its host's React (140 kB for 18, 219 kB for 19, minified), and renders in Chromium with working state. `serve`: a second Vite dev server in `middlewareMode` (`appType: 'custom'`, `base: '/frames/'`, its own `cacheDir`) pre-bundles the host's React into its `cacheDir` and renders, with and without `optimizeDeps.include`; Vite's client is served from `showroom`'s own install. Only virtual files imported by their exact relative path were tried (_`O36`_). Gotchas: `transformIndexHtml` prefixes `base` itself; `envFile` is deprecated in Vite 8 (`envDir: false`).
- _`D245`_ (`live`; resolves the React part of _`O20`_ (PLAN-P4-showcases.md); refines _`D107`_ (PLAN-P4-showcases.md)): **Fixtures on another React than `showroom`'s own carry a lockfile and get their own install**: e.g. a React 18 fixture commits its `package.json` and `package-lock.json`, and the `integration`/`e2e` global setup runs `npm ci` for it once per run into a cache folder under `node_modules/.cache/showroom-tests/`, which its tests copy; CI then needs the npm registry, as `npm ci` already does. Fixtures on `showroom`'s own React keep resolving this repository's `node_modules` (_`D107`_ (PLAN-P4-showcases.md)). The details are _`P7.2`_'s (_`O41`_). Rejected: npm aliases in `showroom`'s devDependencies (`react18: npm:react@^18`), which fail to install (`ERESOLVE`: `react-dom@18`'s peer `react@^18` meets the root's React 19; a scoped `overrides` fails the same way), and `--legacy-peer-deps` (relaxes every install).
  - Evidence: Spike 2026-11-12: a fixture copy with its own `npm install` of React 18, under a repository on React 19, bundles only React 18, from its own `node_modules`; the same copy without its install resolves the repository's React 19.
