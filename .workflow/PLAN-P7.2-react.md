# _`P7.2`_ The `react` showcase adapter

implemented 2026-11-13 (option chosen: "Approve and commit"; _`D351`_); approved 2026-11-13 (option chosen: "Approve and commit (Rec.)"), without a zero-context review; choices _`D340`_–_`D350`_ settled 2026-11-13

## Goals

The `react` built-in showcase adapter (_`D97`_, _`S6.3`_ (SPEC-S6-showcases.md)), built on the `ts` showcase adapter (_`P7.1`_ (PLAN-P7.1-ts.md)), working in `check --showcases`, `build` and `serve` (_`D82`_, _`D102`_ (SPEC-S6-showcases.md), _`D243`_ (PLAN-P7-ts-react.md)): a `tsx` or `jsx` entry point whose default export is a component (_`D230`_, _`D238`_, _`D239`_), rendered with `createRoot` from the host's own React 18 or later (_`D237`_, _`D244`_ (PLAN-P7-ts-react.md)), without StrictMode (_`D240`_), reading the theme as any page does (_`D241`_, all SPEC-S6-showcases.md); type checked as `ts` showcases are; with its showcase adapter example (_`D304`_ (SPEC.md)).

No child segments: the bundling, type checking, errors, `serve` rebuilds and reads all come from _`P7.1`_.

## Decisions

- _`D340`_ (`live`; Q1, the batch's option chosen: "Accept all (Rec.)", for Q1–Q11): **One shared build**: `TsShowcaseAdapter.build()`'s body becomes an exported function both showcase adapters call, with parameters for the module Vite builds, extra virtual modules and extra compiler options for the type check. Rejected: `ReactShowcaseAdapter` extending `TsShowcaseAdapter` (tighter coupling).
- _`D341`_ (`live`; Q2; resolves the "mount module" part of _`O42`_ (PLAN-P7-ts-react.md)): **The mount module** is a generated plain-JavaScript virtual module at an absolute path beside the entry point (e.g. `<entry>.showroom-mount.js`), never written to disk, never among a build's reads nor named by its errors; it imports `createElement` from `react`, `createRoot` from `react-dom/client` and the entry point's default export, and renders it into the showcase frame root. Glossary term **Mount module** (`CONTRIBUTE.md`, added with the code): "the module `showroom` generates for a framework's showcase, which imports its entry point and renders it into the showcase frame root". Rejected: a `\0` id (bare imports wouldn't resolve from the host, _`D244`_ (PLAN-P7-ts-react.md)).
- _`D342`_ (`live`; Q3): **A `react` showcase frame is the `ts` page**: React renders into the showcase frame root, above the console panel (_`D233`_ (SPEC-S6-showcases.md)), which shows the showcase's logs, React's development warnings in `serve`, and uncaught render errors. Rejected: the showcase frame root only.
- _`D343`_ (`live`; Q4; changes _`D239`_ (SPEC-S6-showcases.md); resolves _`O40`_ (PLAN-P7-ts-react.md)): **Only a missing default export fails the build**, at the entry point's line 1 (the bundler's missing-export error on the mount module's import, mapped to the entry point; if Vite only warns, the plugin checks the entry module's exports); a default export React can't render fails at run time, as React's own error, shown in the console panel (_`D342`_). `memo()`, `forwardRef()` and `lazy()` components are objects, which "isn't a function" would wrongly reject. Rejected: checking the default export's type with the type checker (off with `typeCheck: false`, and rejects those components).
- _`D344`_ (`live`; Q5; resolves _`O29`_ (PLAN-P7-ts-react.md); refines _`D237`_ (SPEC-S6-showcases.md)): **React as a host requirement**: `check()` resolves `react` and `react-dom` (their `package.json`) as Node does, from each `react` showcase's documentation file's folder (as `resolveTypeScript()` does), once per folder, type checking or not: an error where either is missing or older than 18, naming the folder and the version found; plus the `ts` showcase adapter's TypeScript requirement for the showcases that type check. Rejected: `react` only.
- _`D345`_ (`live`; Q6; resolves the types part of _`O39`_ (PLAN-P7-ts-react.md)): **React's types as a host requirement where type checking**: `check()` reports an error for a folder whose `react` showcases type check when neither `@types/react` resolves from it nor `react`'s `package.json` names `types` or `typings` ("install @types/react, or set typeCheck: false"); `@types/react-dom` isn't needed, as the mount module isn't type checked. Rejected: no check (TypeScript's own errors at every showcase).
- _`D346`_ (`live`; Q7; resolves the `jsx` part of _`O39`_ (PLAN-P7-ts-react.md); refines _`D238`_ (SPEC-S6-showcases.md) and _`D253`_ (PLAN-P7.1-ts.md)): **JSX settings**: the type check sets `jsx: react-jsx` only where the tsconfig (or its absence) leaves `jsx` unset, as `js` entry points get `allowJs` (_`D283`_ (PLAN-P7.1-ts.md)); a tsconfig's own `jsx` applies as written. The build pins Oxc's automatic runtime (_`D238`_), keeping the tsconfig's `jsxImportSource` (_`D253`_). Rejected: the tsconfig whole (TS17004 on every TSX file without `jsx`); always forcing `react-jsx`.
- _`D347`_ (`live`; Q8; resolves the `jsx` entry point part of _`O39`_ (PLAN-P7-ts-react.md)): **`jsx` entry points are type checked with `allowJs`**, as `ts`'s `js` entry points are (_`D283`_ (PLAN-P7.1-ts.md)). Rejected: never type checking them.
- _`D348`_ (`live`; Q9): **The `react` showcase adapter's options are `ts`'s**: `typeCheck` (default `true`) and `allowJs` (default `false`), validated the same way; a `ts`, `js`, `mts` or `mjs` entry point is an error pointing at the `ts` showcase adapter. Rejected: `typeCheck` only.
- _`D349`_ (`live`; Q10; resolves _`O41`_ (PLAN-P7-ts-react.md); refines _`D245`_ (PLAN-P7-ts-react.md)): **The React 18 fixture's install**: one fixture, `test/fixtures/showcase-react-18/`, with `react`, `react-dom` 18.3.1 and `@types/react` 18 pinned exactly in its committed `package.json` and `package-lock.json`; the `integration` and `e2e` projects' global setup runs `npm ci --no-audit --no-fund` for it into `node_modules/.cache/showroom-tests/installs/showcase-react-18-<lockfile hash>/`, kept across runs while the lockfile is unchanged (local runs are offline after the first), and tests copy it. The `serve` tier uses fixtures on this repository's React 19 only. Dependabot only watches the root, so it never bumps the fixture. Rejected: reinstalling on every run.
- _`D350`_ (`live`; Q11; for _`D304`_ (SPEC.md)): **`examples/react/`**: a mock project on the examples' shared theme (numbers and time, _`D312`_ (SPEC.md)), e.g. a component library with a counter or a stopwatch, showcases with state, props and the theme read from `<html>` (_`D241`_ (SPEC-S6-showcases.md)); its first showcase a linked `.tsx` file shown in `README.md` (_`D315`_ (SPEC.md)); its own `tsconfig.json` (`types: []`, `jsx: react-jsx`), on this repository's React 19 and `@types/react`. Rejected: settling the example's content separately first.
- _`D351`_ (`live`; from _`P7.2`_'s checkpoint, option chosen: "Approve and commit"): **_`P7.2`_'s deviations from its steps, approved**: `resolvePackage()` and `readPackageJson()` (`typecheck/`), `validateTsShowcaseOptions()` and `checkTypeScript()`'s showcase adapter name are generalised and exported, for `react`'s host check, validation and messages; the React 18 fixture installs with `npm ci --ignore-scripts` (React needs no install scripts); `installFixture()` takes its folder as a parameter, for its unit tests; `react` is now a built-in name (`angular` the only planned one), so two tests' lists of showcase adapters include it; the entry chunk is named after the mount module (`<entry>.showroom-mount-<hash>.js`). The bundler reports a missing default export as an error, so _`D343`_'s fallback wasn't needed; the browser check passed ("I see all the showcases rendering and functionaling").

## Steps

1. **The shared build** (`src/adapters/showcase/ts/`): `TsShowcaseAdapter.build()`'s body becomes an exported function both showcase adapters call, taking the module Vite builds (the entry point for `ts`, the mount module for `react`), extra virtual modules, and the type check's extra compiler options; `ts` behaves exactly as before (its tests unchanged).
2. **The `react` showcase adapter** (a new `src/adapters/showcase/react/`, never re-exported, registered as `react`): `validate()` (options, entry point's language); the mount module; the default-export check; `check()` (React, and TypeScript and React's types where type checking); `build()` through the shared build, on the `ts` page.
3. **Type checking React showcases** (`src/adapters/showcase/ts/typecheck/`): the JSX default, and `jsx` entry points as `js` ones.
4. **Fixtures and the React 18 install** (`test/fixtures/showcase-react*/`, `src/testing/setup/`): fixtures on this repository's React 19, and one on React 18 with its committed lockfile, installed once per lockfile into the tests' cache.
5. **Tests** (beside each changed file): unit tests of `validate()`, the mount module's source, `check()` (injected resolvers, and `package.json` files in scratch folders), the type check's JSX default; `integration` tests of builds (React 19 and 18 bundled from the host, a missing default export, a type error in TSX, a `jsx` entry point, a showcase importing a host component and CSS); `e2e`: `build()` on a React fixture; `serve`: a React fixture's showcase frame served.
6. **The showcase adapter example** (`examples/react/`): a mock project on the examples' shared theme (_`D312`_ (SPEC.md)), its own `tsconfig.json`, its first showcase a linked `.tsx` file shown in `README.md` too (_`D315`_ (SPEC.md)), on this repository's own React.
7. **Documentation**: `README.md` (the `react` showcase adapter: format, options, host requirements, the theme, the example); `AGENTS.md` (Layout: `src/adapters/showcase/react/`; Testing: the React tests and the React 18 install; Gotchas as they come); `CONTRIBUTE.md` (project structure; the Glossary's new term); `.github/workflows/ci.yml` only if the install needs it.
8. **Verification**: `npm run ci` green; this repository's showroom built from a copy and served, for the user's browser check of the React example (rendering, state, the theme, the console panel) at the checkpoint.
